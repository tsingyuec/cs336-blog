## 本讲要解决的核心问题（SCQA）

**背景（Situation）**：从这一讲起，课程暂时从"系统"领域抽身，回到更偏深度学习的内容——**缩放定律（scaling laws）**。这两节课的主题与它相关的现象有关；今天先讲基础：核心概念、几篇经典论文、数据缩放律、临界批次大小、学习率缩放，以及"要更多数据还是更大模型"。之后课程会穿插讲推理（inference），再回到更进阶的缩放话题（μP、优化器规模依赖等）。([【跳转到 00:00】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=0)、[【跳转到 00:34】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=34))

**冲突（Complication）**：设想你有个特别有钱的朋友，借给你**一大堆 B200** 用一个月，让你打造一个很棒的开源语言模型。基础设置、数据都准备好了，但你面对的选择多如牛毛：架构怎么选？超参数怎么设？**跑一次大规模实验可能就要花掉几百万美元**——如果靠蛮力在大规模上反复试错，钱花光之前你可能什么都证明不了。([【跳转到 01:03】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=63)、[【跳转到 01:33】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=93))

**疑问（Question）**：我们能不能先把优化都放在小规模上完成，再用一条**简单而稳健的规则**把小规模的结果**外推**到大规模，从而在真正的大训练开始之前就预判它的结果？

**回答（Answer，结论先行）**：能，这就是**缩放定律**——一组简单的预测规则，帮我们从中小规模模型的表现推测大规模下的表现。它的核心经验事实是：**在双对数坐标下，测试损失与数据量、参数量、算力等资源之间往往呈现清晰的线性关系（幂律）**。它之所以好用，是因为损失随规模按可预测的多项式速率衰减；它之所以让人头疼，是因为：

1. 它本质上是**曲线拟合**，并没有"黄金法则"保证一定成立；
2. 它比想象中"看细节"——参数怎么数、学习率/warmup 怎么设、batch size 怎么选，任何看似微不足道的决定，都可能在跨越多个数量级的外推中放大成巨大差异（这正是 Kaplan 与 Chinchilla 之争的根源）；
3. 与其说它自动生效，不如说它是**人为设计出来的、有"下界"性质的产物**——只有沿着好的训练配方扩大规模，它才成立。

本讲会依次走完：数据缩放律 → 幂律的理论直觉 → 数据混合/重复/过滤 → 临界批次大小 → 学习率缩放 → 联合数据-模型缩放律 → Kaplan vs. Chinchilla → 实战注意事项。在大实验室里，缩放律几乎是一种"信仰"乃至"生活方式"；希望学完你能明白它为什么值得信，以及在什么条件下才值得信。([【跳转到 02:31】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=151))

> 本讲一个默认前提：除非特别说明，**模型规模都会大于数据集规模**（处于幂律区间）——通常模型规模比数据量大十倍左右，这样讨论才简单。([【跳转到 17:45】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1065)、[【跳转到 18:24】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1104))

## 一、为什么需要缩放律：把小规模上完成的优化"无损放大"

为什么需要缩放律？因为最直白的做法很浪费：预算充足就多跑几次大型训练、在大规模上直接调超参。更聪明的做法是：**尽量把优化都放在小规模上完成，然后靠一条稳健的规则把小规模的结果外推到大模型**。如果小规模与大规模之间真的存在稳定的规律，你就能对"用缩放方法优化系统"这件事有信心——这正是从工程角度看待缩放律的价值。([【跳转到 02:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=155)、[【跳转到 03:05】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=185))

当然，如果你只是做工程、把文献里的最佳实践照搬过来就够用了（比如讲架构那节课提到的那批公认选择）。但假如你想做**前沿研究**、想做出比市面上最好的模型还强的东西，就必须真正对这些选择下功夫——照抄是抄不出 state-of-the-art 的。([【跳转到 02:04】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=124))

## 二、历史渊源：从泛化界到 Hestness（2017）

缩放律和经典理论联系得很紧，甚至有点像"经验版的样本复杂度"。([【跳转到 03:33】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=213))

### 2.1 泛化界：误差上限依赖样本量

对某个假设类，你可以说"误差最多比模型在训练集上的表现差这么多"。关键在于，这些界限往往**取决于样本量**——这本质上就是在说：随着训练集变大，损失存在一个理论上限。这和"数据变多会发生什么"的思路紧密相关；对更复杂的类别（如平滑密度）也能推出类似的界限。([【跳转到 04:00】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=240)、[【跳转到 04:30】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=270))

### 2.2 早期的"数据缩放律"：1993 年就有了

最早的"数据缩放律"可以追溯到 **1993 年前后**（贝尔实验室的 Cortes、Vapnik 等人）：在非常大的数据集上训练分类器很贵，可以先在较小样本上训练、**画出错误率随样本量衰减的曲线**来估计性能——这几乎就是数据缩放定律。([【跳转到 04:55】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=295)、[【跳转到 05:25】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=325))

**Banko & Brill** 的经典 NLP 参考文献表明：与其把钱花在算法开发上，不如去收集更多数据——从扩展的角度思考，是提升系统性能非常有效的途径。([【跳转到 05:55】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=355))

**Kolachina 等人（2012）**：研究机器翻译中数据量增加时性能遵循的函数形式（看 BLEU 分数），得到的**指数大约是三和四**——和今天的多项式形式并无本质不同。接下来的讲座里你会反复看到指数 3 和 4 的多项式函数；其实早在 2010 年代初大家就大概知道这些函数形式能很好地预测模型表现。([【跳转到 06:29】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=389)、[【跳转到 06:59】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=419))

### 2.3 Hestness（2017）：被低估的前瞻工作

尤其值得提的是 **Hestness 等人（2017）**：这篇工作的引用量其实没达到它应有的水平。它把缩放律构建成**数据集规模的函数**，涵盖语音识别、机器翻译、语言模型等多种系统，发现大量领域都呈现**漂亮的多项式趋势**。它还前瞻性地提到：模型可能因准确率（比损失更不连续）而"突然涌现"某些能力；既然是靠算力扩展，那么提升速度、优化系统最终都会转化为准确率——这些正是我们今天熟悉的现象。**很多"现代"观察，在 LLM 时代之前就已被看清**——如果 2017 年时认真研读并深入思考过这些论文，你其实完全可以预见到大语言模型时代的种种现象。([【跳转到 07:14】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=434)、[【跳转到 07:48】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=468)、[【跳转到 08:18】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=498))

![Hestness 2017：跨任务（机器翻译、语音、语言模型等）的缩放曲线与拟合函数形式 ε(m)=αm^β+γ；右侧给出"小数据区—幂律区—不可约误差区"的示意。](assets/p09/00434.jpg)

### 2.4 课堂问答：缩放律是纯经验拟合吗？

有同学问："这些缩放律只是经验得出的，还是有理论依据？"答案是：缩放律本身是**纯粹的曲线拟合**，但理论为"为什么多项式形式很自然"提供了丰富的来源——统计估计理论经常研究误差如何随变量衰减，会给出各种候选函数形式；物理学家也擅长取极限分析（极限下系统如何表现），同样能给出不同的缩放律函数形式。只是并没有什么黄金法则规定只有这些形式才行。([【跳转到 08:53】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=533)、[【跳转到 09:23】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=563))

## 三、数据缩放律：双对数下的直线

数据缩放律是最简单、最自然的对象，讲者从它讲起，一步步带我们理解"缩放定律的函数形式是如何推测出来的、为什么多项式形式是自然选择"。([【跳转到 09:37】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=577))

### 3.1 设定与预期

固定训练流程、用远超数据规模的模型，不断增加数据量，误差会单调下降，逼近一个无法突破的**不可约误差（irreducible error，也叫噪声底线）**——直觉上形状类似 S 型曲线：从"瞎猜"开始慢慢逼近极限，也就是任务的熵值。([【跳转到 11:22】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=682)、[【跳转到 11:52】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=712))

### 3.2 经验观察：双对数线性

但经验观察是：在**双对数图**上（横轴数据量对数，纵轴测试损失对数），点会呈现非常清晰的**线性趋势**。这张图引自 **Kaplan et al.（2020，OpenAI）**，是后续被反复引用的经典——他们做了很多很棒的消融实验，也有很多很棒的数据。双对数下的直线意味着两件事（[【跳转到 12:13】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=733)、[【跳转到 12:43】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=763)）：

- 误差按**多项式速率**衰减——这是一种**无标度（scale-free）关系**，也就是**幂律（power law）**；
- 我们**离渐近线还很远**——一旦接近不可约误差，曲线会变平缓，而不是保持直线。

![语言模型的数据缩放律：测试损失与数据集大小（token 数）在双对数图上近似直线，拟合形式 L=(D/5.4·10¹³)^{-0.095}，即"幂律"。](assets/p09/00733.jpg)

### 3.3 更奇特的缩放曲线

除了这种最基本的形式，还有更奇特的缩放定律：下游基准测试上有对应的等价形式——随算力变化呈 **S 型（sigmoid）**；甚至有研究直接把**日期**作为横轴来做预测。说来奇怪，至少在这些图里，各种能力的曲线的**上包络线**往往呈线性。没有理由认为那些更奇特的缩放律就一定成立，但实际情况是：语言模型性能随规模和资源的变化，往往比我们一开始以为的更有规律。([【跳转到 10:04】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=604)、[【跳转到 10:34】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=634)、[【跳转到 11:04】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=664))

## 四、幂律的直觉：估计均值与非参数估计

缩放律本质上是曲线拟合，并没有黄金法则规定只能取多项式形式；但用两个最简单的统计估计问题，就能看出幂律有多自然。([【跳转到 13:27】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=807))

### 4.1 例一：估计高斯均值

从高斯分布采样，用经验均值估计真实均值。误差（MSE）为：

```text
E[(μ̂ − μ)²] = σ² / N
```

取其对数，误差是 `N` 的幂函数，双对数斜率约为 `−1`。推广一下：**任何形如"多项式衰减 + 常数"的误差，画在双对数图上并减去常数项后，都会给出一条缩放律**。在参数估计（均值、回归）里，你自然预期得到 `N^{-1}` 量级的速率，不会预期别的——如果你修过统计估计课就知道，经典模型本质上都是 `1/n` 速率（回归可能是 `1/n²` 等）。([【跳转到 13:31】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=811)、[【跳转到 14:01】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=841)、[【跳转到 14:31】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=871))

### 4.2 例二：非参数估计

若估计的不是固定维度的参数，而是一般的平滑函数，做法是把空间切成小格子做局部平均：在 `d` 维里把空间切成边长为 `n^{-1/d}` 的格子，误差约为 `N^{-1/d}`（以 d=2 为例：√n 个格子、每格 √n 个样本、误差约 1/√n）。于是这些更灵活的函数，其缩放律速率不是 `1`，而是 `1/d`——**依赖维度**。([【跳转到 15:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=935)、[【跳转到 16:05】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=965))

### 4.3 神经网络的指数：像高维非参数平滑器

这与神经网络的指数形成鲜明对比。Hestness 与 Kaplan 测得的神经网络收敛指数**远小于 1/2**（大约在 `0.1` 量级，例如 `≈0.076`、`≈0.095`），是**非常慢**的多项式收敛速率。Baker 等人等研究缩放律理论的工作者据此认为：这些指数在告诉我们，**神经网络的行为就像一个高维空间中的非参数平滑器**。这个直觉是否要完全接受因人而异（讲者也坦言它的证据可能有点站不住脚，依赖于对内在维度的估计），但想到这些指数在某种程度上刻画了模型"真正的学习速度"，相当有意思。([【跳转到 15:08】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=908)、[【跳转到 16:59】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1019))

![非参数学习的缩放律：在 2D 单位盒上把空间切成边长为 n^(-1/4) 的小格子，误差 ≈ 1/√n；推广到 d 维得到误差 ≈ n^{-1/d}，即"灵活的非参数学习具有依赖维度的缩放律"。](assets/p09/00995.jpg)

## 五、数据工程：混合、重复与过滤的最优策略都会随规模变化

数据缩放律本身其实没那么有用：它只告诉你"模型学得多快"，对预测有点用，但工程上你更关心的是别的决策——数据混合比例怎么定？该不该重复使用数据？过滤该多狠？在重复用数据这件事上还有很多别的操作可做。([【跳转到 18:33】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1113)、[【跳转到 18:37】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1117))

### 5.1 数据混合：斜率由模型类别决定，组成只改变截距

一个关键洞察是：**数据集的组成会影响缩放律的截距，但斜率由模型类别决定，不随数据分布改变**。把缩放律的由来看作泛化界限的经验版，这一点就顺理成章。于是你可以用极少量数据训练很小的模型，拟合不同混合比例对性能的影响，再外推到全量训练，找出最优配比——思路和外推数据缩放定律完全一样。理论上的玩具模型（线性回归、两个数据源）也印证了"数据多样性越高越有帮助"——只拿一种数据误差都很高，把两种数据混着用总是更好；把截距的变化写下来，就能得到很有意思的见解。([【跳转到 19:12】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1152)、[【跳转到 19:42】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1182)、[【跳转到 20:07】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1207))

不过现实比理想模型嘈杂得多——很多团队的做法是**直接训练一堆小模型、选出最好的数据配比再放大**，根本不做缩放拟合。这恰好印证了"斜率不变、选比例可靠"这个逻辑：只要斜率不变，小规模下最好的配比在大规模下往往依然最好。([【跳转到 21:07】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1267)、[【跳转到 21:41】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1301))

![数据分布偏移的缩放律：数据组成只影响截距、不影响斜率；因此小规模上找到的最优混合比例可以外推到大算力。](assets/p09/01182.jpg)

### 5.2 数据重复：约 4 个 epoch 内几乎不受影响

算力在涨、数据没涨，于是重复使用数据成为常态。"Scaling Data-Constrained Language Models" 研究表明：用标准训练方法，**最多约 4 个 epoch 几乎不受影响**；超过这个临界点后，实际的缩放律会明显差于"把重复数据当作新数据"的预测，不过也可以写出修正后的函数形式来预测重复训练的效果。([【跳转到 21:48】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1308)、[【跳转到 22:18】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1338))

一项把思路推到极致的后续研究（讲者与 Percy 及一名学生合作）探索了**算力无限**时的极限：你想跑多少次 epoch 就跑多少次，能得到的最好结果是什么？结论是：**光靠反复遍历数据不行，无限放大模型也不行**——两条路都收益递减，只能另辟蹊径（比如集成多个模型、从数据里再多榨出一些东西）。有趣的是，各种干预（蒸馏、集成学习等）虽然确实提高了性能，但**斜率出奇地相似**——这是个经验之谈：一旦你开始拟合自己的缩放定律，就会发现斜率通常不变，干预往往只改变缩放律的截距。([【跳转到 22:33】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1353)、[【跳转到 23:07】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1387)、[【跳转到 23:29】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1409))

![数据重复下的缩放律：前约 4 个 epoch 与使用新数据几乎等效，之后收益急剧递减；右图为"分配算力时重复 vs 唯一数据"的效率前沿。](assets/p09/01338.jpg)

### 5.3 数据过滤：最优策略随规模动态变化

**最优过滤策略也会随规模变化**：算力少时，应该下手狠一点、只留最高质量的数据（反正你也用不完整个互联网）；算力充足时，就要逐渐放宽过滤、开始使用质量没那么高的数据（避免反复使用高质量数据）。所以数据过滤、数据质量这些平时看似固定的选择，其实都是**动态**的：规模一上去，你就得琢磨剩下的数据去哪儿找，过滤规则不能一成不变。([【跳转到 23:44】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1424)、[【跳转到 24:14】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1454))

### 5.4 一个方法论陷阱与一个坐标轴笑话

这一部分（从统计机器学习角度看）其实非常简单直接：增加数据量，性能就以非常可预测的方式提升——模型这么大还能按多项式规律变好，挺酷但也没到离谱的程度。不过有个坐标轴的小插曲值得一提：讲者展示"无限算力下预训练"的图时，横轴看起来是线性的，实际上是被错误的坐标轴"美化"过的**对数刻度**（每次翻倍）——而纵轴因为范围极小，线性与对数刻度看起来差不多。拟合出的函数形式依然是多项式。由此引出一个方法论警告：**如果你只覆盖很窄的算力区间，几乎无法判断曲线到底是多项式还是指数增长**——毕竟有泰勒近似在，把局部放得足够大，什么都像线性的。所以不管它是什么函数形式，心里都得留个心眼，保持点怀疑。([【跳转到 25:11】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1511)、[【跳转到 25:48】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1548))

## 六、缩放律作为"判断标准"：架构、优化器、深度宽度、MoE

除了数据，缩放分析还能回答架构与超参数问题。核心方法是：**在多个算力范围内训练一批较小的模型，比较它们的缩放曲线**——看谁的截距更低、斜率更好；如果某个改动的斜率更差，就意味着规模越大它越吃亏，绝不能在大规模上采用。这一节的前提是"你得先相信缩放律"，但信了之后完全可以自己动手验证。([【跳转到 26:10】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1570)、[【跳转到 26:40】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1600))

### 6.1 Transformer 真的比 LSTM 好吗？

最笨的办法是花大价钱训一个巨型 LSTM 做到 GPT-2 甚至更大的规模；缩放律的思路则是训练一批不同层数的 LSTM 和 Transformer，比较缩放趋势。LSTM 的截距肯定不同、斜率可能也不同——如果斜率更差，就不该选它。顺带一提，LSTM/状态空间模型这类结构并非不能用（它们能拟合分布，Mamba 的出现也证明了 SSM 行得通），问题在于**缩放趋势**。这也是为什么现代架构论文（Mamba、Gated DeltaNet 等）几乎都会给出这种对比图：新模型必须**要么整体在 vanilla transformer 上方、要么斜率更好**，否则随着规模做大会反被超越——你肯定不想看到斜率更差的情况。([【跳转到 27:28】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1648)、[【跳转到 27:58】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1678)、[【跳转到 28:28】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1708))

![架构缩放研究：把 transformer 与 LSTM 放在不同算力区间训练并比较趋势——这是"不用训练巨型模型就能分析架构"的标准方法。](assets/p09/01648.jpg)

### 6.2 架构缩放研究：EK 等人（Google）

讲者觉得最近关于架构缩放定律的好论文不算多，但他很喜欢 Google 的 EK 等人的一项研究：他们对 Transformer 风格的模型做了一整套缩放研究，训练了在不同架构上不断扩大的 Transformer 变体，并且**精准捕捉到了现在前沿模型里用的那些架构改动**——门控线性单元（GLU）在所有缩放趋势上都优于基线；Switch Transformer 的趋势不错；softmax 混合也是有效改进（虽然现在已不用）；而一些高效注意力替代方案（如 Performer）则没有做。这些实验的算力远小于今天的训练规模，却仍然观察到了**推动前沿模型发展的趋势**。这就是为什么很多人几乎把缩放律当作一种"范式化判断标准"：如果某个改动没在缩放曲线上体现出来，它就不是一个好的、能随规模受益的改动——某种程度上，很多过去的研究已经反映了我们今天看到的现象。([【跳转到 28:37】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1717)、[【跳转到 29:43】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1783))

### 6.3 SGD 比 Adam 好还是差？

做同样的缩放分析（这是 Hestness 的工作，用的是循环高速公路网络做语言模型）：截距不同，但**斜率非常接近**——即使是从 SGD 换到 Adam 这么大的改动，也很少会改变斜率。这个"固定数据和模型、斜率往往不变"的现象每次看到都让人惊讶，但确实如此。([【跳转到 30:13】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1813))

### 6.4 深度与宽度：寻找尺度不变量

层数太少对模型非常不利（只有一层基本没戏）；只要超过一层，表现就出人意料地有竞争力；在每个算力水平下，更深的模型（在该实验范围内）至少效果更好。更犀利的做法（Kaplan 等人）是寻找**尺度不变量**：层数不是尺度不变量（模型越大确实需要更多层），而**纵横比**（模型维度 ÷ 层数）大致是——不同规模下最优纵横比基本不变，约为**每层对应 100 维**（对更深的模型会稍微偏小一点）。对注意力头数等其他量也可以做类似分析。所以你可以固定纵横比去扩大规模，并画出图让自己确信：随着模型越来越大，优化点并没有偏移太多。([【跳转到 30:43】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1843)、[【跳转到 31:13】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1873)、[【跳转到 31:22】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1882))

![深度/宽度缩放：1 层 vs 2 层差异巨大；超过 1 层后收益递减、更多层（在该范围）更好。](assets/p09/01843.jpg)

### 6.5 并非所有参数都同等重要

你的缩放律看起来是好是坏，取决于你怎么定义"参数"。Kaplan 那篇论文里就观察到：如果把 embedding 参数算进去，深度方向的缩放曲线形状会非常古怪——于是他们决定把所有 embedding 参数排除，只统计"真正在做计算"的非 embedding 参数（你可以这样说服自己，或者随便找个理由；这会对某些结果的有效性产生不小的影响，第九节还会讲）。这说明缩放律不是魔法——Percy 喜欢强调这一点：**缩放律以及这种跨尺度的可预测性，都是人为设计出来的**。这些效果不会自动出现，你得下功夫选对横轴指标、确保超参数不掉队，才能在跨越多个数量级的算力下实现可预测的缩放。这也正是很多缩放律研究者的日常工作：琢磨怎么让缩放变得高度可预测。([【跳转到 32:22】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1942)、[【跳转到 32:52】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=1972)、[【跳转到 33:22】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2002))

### 6.6 MoE 的"参数价值"

如今 MoE 基本成了训练大模型的主流方式，参数总量与激活参数数量解耦了，那么"价值/参数"在新世界里指什么？苹果和 MIT 的一些人做了漂亮的分析：缩放趋势既取决于**总参数**、也取决于**激活参数**。一个直观结果是——当你增加总参数、最小化损失时，得到的模型会越来越**稀疏**；同理，激活参数的数量会随 MoE 稀疏度提高而下降。你可以为不同计算量画出这些曲面，问自己"更愿意把算力花在激活参数上，还是想要多大的稀疏度"——你完全可以在几乎不改变算力的前提下灵活调整稀疏度。更反直觉的是：即便把激活参数固定、只增加"空参数"，损失仍会下降——**那些未激活的参数仍在帮你降低损失**，并且这些量都遵循可预测的缩放规律。([【跳转到 33:39】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2019)、[【跳转到 34:09】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2049)、[【跳转到 34:39】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2079)、[【跳转到 35:11】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2111))

![MoE 的"参数价值"：损失随总参数与激活参数共同变化；最优稀疏度随规模提高，且未激活参数也贡献损失下降。](assets/p09/02019.jpg)

## 七、两个必须重新琢磨的旋钮：临界批次大小与学习率缩放

准备训练新模型时，讲者说大部分东西其实都是固定的（你不太会激进到换掉 Transformer，多半会选经过验证的、受 DeepSeek 启发的 MoE 架构之类）。但**两件事你确实得重新琢磨：batch size 和 learning rate**——训练过深度学习模型的人都知道这两个量必须谨慎搭配，改一个另一个就得跟着改。而 batch size 还从上一讲知道有另一个麻烦：我们希望它越大越好，因为**数据并行需要大 batch**。([【跳转到 35:16】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2116)、[【跳转到 35:46】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2146))

### 7.1 临界批次大小：噪声受限 vs 偏差受限

真正想知道的是：**在性能开始变差之前，batch size 最大能开到多少？它又如何随模型规模变化？** 这就是**临界批次大小（critical batch size）**：在某个临界点之前，增大 batch 的收益是成正比的；过了这个点，回报就开始打折扣。([【跳转到 36:16】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2176))

- **噪声受限阶段（noise-limited）**：往 batch 里每多加一个样本，都能降低 SGD 梯度里的噪声。此时**方差**是主要限制，方差一降效果提升就非常明显——缩放是**完美**的。
- **偏差受限阶段（bias-limited）**：当你到达梯度噪声尺度那个点，就不再受方差限制了。回想梯度下降：你看到的只是目标函数的**局部结构**，没法从全局看清最小值在哪，哪怕把噪声压得再低，你找到的局部下降方向与全局最优之间**总有差距**。此时限制你的是**偏差**，收益开始递减——进入**低效缩放**。

([【跳转到 36:46】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2206)、[【跳转到 37:16】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2236)、[【跳转到 37:46】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2266))

![临界批次大小：左侧等高线示意小 batch 与大 batch 的下降路径；右侧显示预测的训练速度——临界点前是完美缩放，之后进入低效缩放。](assets/p09/02176.jpg)

### 7.2 怎么估：四步流程

临界批次大小是从一系列复杂计算（对目标函数的局部二次近似）中推导出来的，但实际估算步骤并不复杂（[【跳转到 38:34】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2314)、[【跳转到 39:13】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2353)、[【跳转到 39:43】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2383)）：

1. 选定一个**目标损失**（你想尽快达到的损失值）；
2. 遍历不同的 batch size，记录达到目标所需的**步数 S** 和**样本总数 E**（两者相差一个 batch 的倍数：步数 × batch = 样本总量）；
3. 把两者对"理论最小步数/样本数"归一化，写出权衡关系：

```text
S / S_min − 1 = (E / E_min − 1)^(−1)
```

4. 拟合出 `S_min`、`E_min`，然后取它们的比值：

```text
B_crit = E_min / S_min
```

它的意义是：**在不显著增加步数的前提下优化收敛速率**——给出的步数会比绝对最优稍多、样本也稍多，但实现了两方面的平衡（大约是 2 倍步数/样本）。另一个补充视角：这个量也接近于"梯度协方差与梯度平方范数之比"（细节见原论文）。

### 7.3 为什么它随规模变大

把它放进缩放律讲，是因为**随着目标损失降低（也就是训练得越来越好），临界 batch size 会以非常可预测的方式增长，大致呈反多项式形式**。这很合理：越接近最优点，你要最小化的差异越细微，噪声的影响就越大，因此方差缩减的收益也越大。所以超大规模训练跑到图表最右侧时，batch size 可以设得很大。([【跳转到 40:58】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2458)、[【跳转到 41:28】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2488))

![临界批次大小的定义：扫过不同 batch、拟合归一化权衡曲线，B_crit = E_min / S_min。](assets/p09/02314.jpg)

### 7.4 学习率缩放：预测最优点，或重参数化让最优点不动

学习率这边同样有点复杂，两种主流思路（[【跳转到 41:43】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2503)、[【跳转到 42:13】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2533)、[【跳转到 42:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2555)）：

1. **预测最优点**：例如只做宽度缩放时，模型越宽、参数越多，学习率就该设得越小（"一次改动的东西更多了，步子应该迈小点"）。常见经验法则是按宽度的倒数调整（`LR ∝ 1/width`）。最优点的变化规律相当可预测，所以这思路并不离谱。
2. **重参数化（reparameterization）**：改变初始化大小、针对网络的不同部分调整优化器步长，**迫使模型在不同规模下保持相同的最优学习率**，于是可以直接选定最佳学习率开跑。这类方法统称 **μP（maximal update parametrization，最大更新参数化）** 等；有人报告效果显著，也有人报告没那么好。

两种方法都已在大规模实践中成功应用；讲者个人感觉现在更多人偏向缩放律那套，但两种思路都行得通，细节留到进阶课。([【跳转到 42:55】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2575)、[【跳转到 43:29】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2609))

## 八、要更多数据还是更大模型：联合缩放律与 Kaplan 的结论

缩放律最知名的应用场景，就是**分配固定算力**。你拥有的资源是 FLOPs，而数据量与参数量大致与 FLOPs 成正比（数据 × 参数 ≈ 算力，Percy 第一堂课讲过），问题于是变成："我该要更多数据，还是更大模型？"

最直观的浪费是：拿一个极小的模型灌入海量数据，纯属浪费——它的表现在很长一段时间里都没什么起色（图上那条深紫色的线）。同样的算力拿来训练一个大模型、喂同样甚至更少的 token，效果会好得多。**只要搞懂数据量和模型大小是怎么结合起来影响性能的，你就能把算力分配优化得非常精准。**([【跳转到 48:38】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2918)、[【跳转到 48:56】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2936)、[【跳转到 49:26】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2966))

**联合数据-模型缩放律**同时描述两个变量。Rosenfeld（2020）给出极简形式——两个倒数项相加：

```text
Error = n^(−a) + m^(−b) + C
```

Kaplan（2020）则用：

```text
Error = (m^(−α) + n^(−1))^β
```

两者形式等价、略有不同。取极限可以校验其合理性：数据无限大时，误差趋近于由模型规模决定的下限（退化为纯模型缩放律）；模型无限大时，限制你的变成数据（退化为纯数据缩放律）。**以后有人给你讲某个缩放定律，建议你试试对所有变量取极限**，这样能帮你更好地理解系统的行为。这类联合规律在**低计算量、低数据量的点上**拟合后，能相当准地外推到大数据量或大模型规模。([【跳转到 49:56】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2996)、[【跳转到 50:26】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3026)、[【跳转到 50:34】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3034))

![联合数据-模型缩放律：Rosenfeld 2020 给出 Error = n^(−a) + m^(−b) + C，Kaplan 2020 给出等价形式；取极限可分别退化回纯模型/纯数据缩放律。](assets/p09/02996.jpg)

有了它，"固定 FLOPs 下最小化损失"就变成一个简单的非线性优化问题。解出来（Kaplan 的结论）大致是（[【跳转到 51:30】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3090)、[【跳转到 52:00】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3120)）：

```text
N（参数量） ∝ C^0.73
D（数据量） ∝ C^0.27
```

也就是**随着算力增长，参数量增长得更快，每个参数分到的 token 数反而减少**——这就是"训练越来越大模型"的建议。GPT-3 时代大家都在训练动辄数千亿乃至万亿参数的稠密模型，部分正是被这一预测推动的：大家看到了 GPT-3、看到了 Kaplan 的预测，就想"我要用超大规模的模型来跑我的大型训练"。

## 九、Kaplan vs. Chinchilla：三种方法、三种分歧根源，以及"缩放律是下界"

### 9.1 Chinchilla 的挑战

几年后（2022），DeepMind 的 **Hoffman 等人（Chinchilla）** 指出 Kaplan 的预测**偏差很大**：之前大家都被引导去训练"太大"的巨型模型（图中那三个星号），而真正该训的是**小得多**的模型（青色星号）——约 **每个参数 20 个 token**。Chinchilla 提出了**三种独立估计最优权衡的方法**，以增强稳健性、抵御建模假设带来的风险（除了方法三略有不同外，前两种大体一致，数据/模型的系数约为 0.49/0.51）：([【跳转到 52:30】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3150)、[【跳转到 53:45】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3225))

![Kaplan 的预测 vs Chinchilla 的修正：Kaplan 认为应训练巨型稠密模型（右上星号）；Chinchilla 表明更小、更多 token 的模型（青色星号）才是最优。](assets/p09/03150.jpg)

### 9.2 三种方法

1. **下包络线法（minimum over runs）**：把所有训练曲线拿来，提取每条曲线对给定 FLOPs 能达到的**最低损失**（下包络），因为每个点对应一次训练、一个模型规模，于是可以画出"FLOP 预算 → 最优模型规模"的散点，拟合出线性趋势。按他们的预算得到约 **67B 参数**。方法直观，但要定义下包络本身并不容易。([【跳转到 54:15】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3255)、[【跳转到 55:03】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3303))
2. **IsoFLOP 法**（讲者个人最喜欢、最简单稳健、现在也非常流行）：选定一组 FLOP 预算（例如按 3 的倍数递增），对每个预算**固定 FLOPs、在"参数 vs 数据"这个维度上扫一遍**（比如数据加倍、参数减半），最终损失会形成一条曲线；取每条曲线的最小值（或拟合二次函数取极小），穿过所有极小点即得最优关系，给出约 **63B 参数**，与前一方法吻合得很好。([【跳转到 55:33】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3333)、[【跳转到 56:33】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3393))

![IsoFLOP 法：固定每个 FLOP 预算、扫描参数/数据权衡，取损失曲线的极小值，穿过所有极小点得到最优模型规模。](assets/p09/03333.jpg)

3. **联合函数拟合**：直接假设一个描述"模型大小与数据量如何共同影响损失"的函数形式（Rosenfeld 和 Kaplan 其实都提出了这种思路），对所有训练数据做曲线拟合。这是最"笨"也最自然的方法，但曲线拟合怎么做非常关键（变量多、曲面拟合棘手，和方法一一样有点麻烦，不像 IsoFLOP 那样直接）。它给出的系数是 **0.46/0.54**，与前两种（约 0.50/0.51）略有不同：前两种大体意味着参数量和 token 数**等比例扩展**（固定比例，20 倍系数由此而来），而方法三从渐近意义上看意味着 **token 数会远远多于参数量**——这个不一致困扰了不少人。([【跳转到 56:42】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3402)、[【跳转到 57:17】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3437)、[【跳转到 57:33】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3453))

### 9.3 分歧根源：一堆"微不足道"的细节

要先说明：Chinchilla 的做法和 Kaplan 并没有本质区别——并不是 Kaplan 搞了个疯狂的实验、而 Chinchilla 的作者们更聪明；两边做的事都挺合理，但缩放预测的差别却很大。缩放定律其实**非常看细节**：你具体怎么实施、超参数怎么设、甚至连 X 轴怎么画，都会让它大变样。有篇题为 "Resolving Discrepancies in Compute-Optimal Scaling of Language Models" 的论文（最后一位作者曾是斯坦福学生）用一系列实验说明这一点：先用与 Kaplan 相近的设置复现 Kaplan 的结果；换一种参数计数方式，曲线稍动；调整 learning rate warmup，曲线再偏一点；再把 optimizer 调一调——结果就完全吻合 Chinchilla 了。**是一连串看似微不足道的决定，累积成了 Kaplan 与 Chinchilla 之间的巨大差距**（[【跳转到 58:07】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3487)、[【跳转到 58:37】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3517)、[【跳转到 59:07】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3547))：

- **参数计数方式**：前面说过 Kaplan 排除了 embedding 参数（这本身问题不大），但他们**连最后一层（softmax 线性层）的参数也漏掉了**——因为在很多模型里 embedding 层与最后一层互为对偶（形状分别是 `词表×隐藏维` 与 `隐藏维×词表`），他们心想"干脆两个都排除算了"。包不包括这些参数，对缩放律的形状影响巨大——这**与其说是观点不同，不如说是个疏忽**。
- **学习率与 warmup**：Kaplan 训练的模型其实**特别小**，小到 warmup 做完时模型**还没收敛**；他们的学习率设置很不理想，模型没有训充分。
- **batch size**：Kaplan 用了**固定的较大 batch**，这对小模型并非最优。改用随规模变化的 batch size，结果就会与 Chinchilla 吻合。

另一个重要视角（Pearce 等人）用另一种巧妙办法验证：直接拿 Chinchilla 训练曲线隐含的函数形式，模拟"如果忽略 embedding 参数并大幅缩减规模，Kaplan 的隐含训练曲线会怎样"。他们发现主要有两个效应：一是 **Kaplan 在低得多的计算规模下运行**，对微小变化极其敏感；二是**忽略非 embedding 参数这个改动足够大**，足以导致与 Chinchilla 的偏差。所以他们的论点与上一篇论文略不同：这里其实是"计算规模的大小"加上"非 embedding 参数引起的轻微非线性"共同导致了不一致。([【跳转到 61:16】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3676)、[【跳转到 61:46】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3706))

### 9.4 方法三的谜团：作者比他们自己以为的更正确

Chinchilla 某种程度上推翻了 Kaplan，但还剩一个谜团：**方法三从来都和方法一、方法二对不上**，数字看起来差异不大、作者们也显得毫不在意，但这背后的含义其实相当重要——方法一、二意味着参数和 token 等比例扩展（20 倍系数由此而来），而方法三的指数不同，意味着渐进上 token 数会远远多于参数量。对此感到不安的不止讲者一个：**EPFL 的几个人**既拿不到原始数据也拿不到代码，于是**从论文图表里提取数据、重新拟合方法三的曲面**，发现原论文当初一定是对数据**欠拟合**了；重新拟合后的损失值能低得多，而且结果**几乎完全吻合"每参数 20 token"的经验法则**。也就是说，Chinchilla 的作者其实**比他们自己以为的更正确**，方法三最终也被证明是稳健的——得知这个方法其实挺稳健，还是挺让人欣慰的。([【跳转到 62:28】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3748)、[【跳转到 63:22】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3802)、[【跳转到 63:52】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3832))

### 9.5 关键认识：缩放律是一种"下界"

由此得到一个重要认识（[【跳转到 60:37】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3637)、[【跳转到 61:07】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3667)）：

> **缩放律在某种意义上是一种"下界"。** 如果你沿用一套好的配方并扩大规模，就能得到这样的结果；但如果你去扩大一个**本不该扩大的配方**（比如 warmup 设得离谱、batch 不合理），得到的缩放定律就会很差。所以要尽可能接近标准的、完整的训练流程。在确立可靠的缩放定律方面，很多工作其实是在**找对正确的运行区间**，这样你在不同计算规模下才能获得可靠的缩放。

## 十、实战与注意事项：过度训练、迁移不确定性、方差与 IsoFLOP

### 10.1 你可能并不真的需要 Chinchilla factor

如今这几乎是常识。如果你训练的是**生产用模型**，多数情况下并不太在乎省训练算力——看看各种关于前沿实验室怎么花算力的外部调研就知道：大部分算力其实花在**研发与推理服务**上，而非训练本身。为了推理服务，你想要的其实是"能力够用的小模型"，而不是又大又臃肿、部署很贵的模型（哪怕它能把训练成本压到最低）。所以真正想要的是**"过度训练"（over-training）**——加引号是因为过度训练其实正是我们想要的，这才是训练量刚刚好。([【跳转到 64:27】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3867)、[【跳转到 64:57】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3897))

回看早期发布的模型：GPT-3 肯定属于欠训练（约每参数 2–3 个 token），Chinchilla 达到了 20 的现代比例；之后一段时间大家维持在约 7——那是个模型服务化还不普遍的时代；随着服务变得切实可行，人们开始主动过度训练、转向 MoE，并做出各种为推理优化的权衡。（幻灯片上的例子：LLaMA 65B 约 22、Llama 2 70B 约 29、Mistral 7B 约 110、Llama 3 70B 约 215 token/参数——预期使用越多，越值得付前期训练成本。）所以 Chinchilla 重要的原因，并不是"20:1 是唯一黄金比例"（做研究时或许适用），而是**它告诉了我们很多关于如何拟合缩放定律、如何思考缩放定律的东西**。([【跳转到 65:27】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3927)、[【跳转到 65:57】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3957))

![过度训练：GPT-3 约 2 token/参数、Chinchilla 20，而 Llama 3 70B 已达 215——生产模型为降低推理成本主动"多训"。](assets/p09/03897.jpg)

### 10.2 上游（perplexity）与下游（benchmark）未必一致

这一节最后想强调：**上游与下游的性能表现可能大不相同**。看 log-likelihood/perplexity 这类指标——比如架构论文里的例子——它与参数量高度相关，是一条非常漂亮的线性趋势；可当你准备上线"最强"的模型时，却发现参数量更大、perplexity 更好的模型反而不是下游最优的。这种情况在上下游之间很常见，而且这大概是讲者见过的上下游之间最差的相关性。要记住：**缩放定律一般用在 perplexity 这一侧，非常干净、规律、可预测；但从 perplexity 迁移到下游，远没有看上去那么确定。**([【跳转到 43:41】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2621)、[【跳转到 44:11】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2651)、[【跳转到 44:41】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2681))

讲者还讲了个小插曲：以前有学生去各家做 post-training，回来总抱怨"搞 pre-training 的人把模型甩给你，说 perplexity 挺好看，剩下的都是你的问题了"——可问题往往在 pre-training 阶段就埋下了。所以**别做那种人**，要认真考虑迁移。这也引出缩放律的核心理念：**先在低方差的度量（perplexity）上把规律立住，再依靠某种关于迁移的信念、或在别处另行确立迁移能力，来证明它能迁移到下游。**([【跳转到 47:23】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2843)、[【跳转到 47:34】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2854))

### 10.3 方差：单次运行够不够？

有同学问：缩放律图上每个数据点的方差如何？一般跑几次、聚合时取平均还是中位数？据讲者所知，**几乎所有情况都是单次运行（single run）**——因为 perplexity 非常稳定：训练数据同质、数据量大、batch 大，重新跑一遍方差可能只在小数点后第二位。很多预训练代码库甚至没有验证损失——因为单遍（single-pass）训练下训练集和验证集的结果几乎一样，这也是为什么很多图会把这两个指标互换。但研究 learning rate 或 critical batch size 的缩放律时，波动会剧烈得多；大家确实会做些方差缩减，但这套做法其实没那么普遍，按理说应该更常见。直接在下游 benchmark 指标上做缩放定律的人也有，但同样有噪声问题。([【跳转到 45:58】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2758)、[【跳转到 46:20】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2780)、[【跳转到 46:30】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2790))

### 10.4 朴素流程与"先预测再开跑"

在跑大规模训练之前，你得先对结果有个大概的预期，别只问"能不能跑通"——如果参考缩放定律，你应该能**相当精确地预测数值**，比如"这个优化器能带来多少提升"。朴素流程是：先训练一批小模型，在双对数图上拟合直线、确立缩放律；只要拟合足够好，就有理由相信这个差距会一直存在，再把缩放律直接应用到大规模训练。这在实践中足够准确——你还能怎么做呢？凭空搞个训练出来不太可能好。([【跳转到 45:05】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2705)、[【跳转到 45:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=2735))

### 10.5 IsoFLOP：经久不衰的研究工具

IsoFLOP 作为一个研究工具一直经久不衰：定好一个 FLOP 预算，扫遍其他所有自由度，看看曲面大概长什么样——通常就能得到相当可靠的读数，看出差异有多大。扩散模型的研究（讲者有个学生做过）、前面提到的 MoE 研究都采用了 IsoFLOP 风格的设计。**当你需要权衡多个因素时，IsoFLOP 是很好的默认选择。**([【跳转到 66:06】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3966)、[【跳转到 66:36】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3996))

课堂尾声还有个开放性讨论：如果循环 Transformer（recurrent transformer）这类架构流行起来，并行系统会怎样？讲者不太相信那些传闻，但好问题在于：FSDP 这类机制本质上依赖"取权重、丢权重、再取权重"的循环，而权重常驻的架构不需要反复取权重、参数效率高得多——很多模型并行相关的东西可能就没那么重要了。([【跳转到 54:51】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3291)、[【跳转到 55:24】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=9&t=3324))

## 小结

![本讲回顾：数据缩放理解数据的理论；模型缩放大幅降低训练成本；缩放作为预测工具，让你知道哪些问题可以被"大力出奇迹"。](assets/p09/04032.jpg)

1. **缩放律是一组简单的预测规则**，把中小规模的表现外推到大模型，让规模化工程不必真的先跑大规模训练；在大实验室里它几乎是一种"信仰"，但前提是你明白它**由人为设计、且有下界性质**。
2. **它不是新东西**：从泛化界（误差界限依赖样本量），到 1993 年前后"小样本训练 + 外推"的做法，到 Banko & Brill、"指数 3 和 4"的机器翻译研究，再到 Hestness（2017）跨任务的漂亮多项式趋势——很多"现代"观察在 LLM 时代前就已被看清。
3. **数据缩放律**：双对数下近似线性，误差按幂律衰减（指数约 `0.1`，远小于参数估计的 `1/2`），这暗示神经网络像高维空间里的非参数平滑器。
4. **数据工程的最优策略随规模变化**：混合组成只改变截距、不改变斜率（所以小规模选配比再放大可靠）；约 4 个 epoch 内的重复几乎无损失，超过则要修正缩放律；过滤规则也应随算力从"狠"变"松"。
5. **临界批次大小**区分了"完美缩放"（噪声受限）与"低效缩放"（偏差受限），并随目标损失降低而以可预测方式增大；估计它只需选目标损失、扫 batch、拟合 `B_crit = E_min/S_min`。
6. **学习率**既可预测最优点（如按宽度倒数 `LR ∝ 1/width`），也可通过 **μP 等重参数化**保持最优学习率不变。
7. **联合数据-模型缩放律**把"要更多数据还是更大模型"变成可解的优化问题；Kaplan 建议 `N ∝ C^0.73`、`D ∝ C^0.27`（越训越大），而 Chinchilla 纠正为约**每个参数 20 token**，并用**下包络、IsoFLOP、联合拟合**三种方法交叉验证；二者的分歧源于参数计数、warmup/学习率、batch size 等细节——**缩放律是一种下界，只有沿着好配方扩大规模才成立**。
8. **生产实践中常主动"过度训练"小模型以优化推理成本**；同时要警惕 perplexity 与下游任务之间的迁移不确定性；perplexity 方差极低可用单次运行，而学习率/临界批次的研究需方差缩减；**isoFLOP 是"需要权衡多个因素"时的默认研究工具**。

本讲的最后引出一句提醒：缩放律能预测"哪些问题可以被大力出奇迹"，但下一讲的主题（推理）同样重要——毕竟真实部署中大部分算力花在推理侧。下一讲由 Percy 讲推理，之后我们再回到更进阶的小众缩放话题。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| 缩放定律（scaling law） | 用中小规模训练结果外推大模型表现的预测规则 |
| 幂律 / 无标度 | 双对数图上的直线关系，误差按多项式速率衰减 |
| 双对数图（log-log plot） | 横纵轴都取对数画图；直线即幂律、斜率即指数 |
| 不可约误差 | 任务本身的噪声底线，再多的数据也无法突破 |
| 参数估计 / 非参数估计 | 固定维度参数的估计（速率约 N⁻¹）与一般平滑函数的估计（速率约 N^(−1/d)） |
| 分布偏移缩放律 | 描述数据组成如何影响性能：只影响截距、不改斜率 |
| 数据重复 | 有限数据被多次训练；约 4 epoch 内几乎无损，之后收益递减 |
| 过度训练（over-training） | 主动用比 Chinchilla 最优更多的 token 训练小模型，以降低推理成本 |
| 临界批次大小 | batch 收益从"完美缩放"转为"递减"的转折点，B_crit=E_min/S_min |
| 噪声受限 / 偏差受限 | 临界点前受梯度噪声（方差）限制；之后受局部方向与全局最优的偏差限制 |
| IsoFLOP | 固定 FLOP 预算、扫描参数/数据权衡来寻找最优模型规模的方法 |
| 下包络线法 | 取每个 FLOP 预算下所有训练曲线的最低损失，拟合最优模型规模 |
| 联合数据-模型缩放律 | 同时描述数据量 n 与模型规模 m 对误差影响的函数形式 |
| Chinchilla factor | "每个参数约 20 个 token"的计算最优经验比例 |
| μP（最大更新参数化） | 通过重参数化让不同规模模型共享同一最优学习率的初始化方案 |
| perplexity | 困惑度，语言模型的低方差上游指标，缩放律的主要拟合对象 |
| 内部/外部效度（上游/下游） | perplexity 上的规律不一定迁移到下游 benchmark 表现 |
| single run | 每个配置只跑一次的实验约定；依赖 perplexity 的低方差 |
