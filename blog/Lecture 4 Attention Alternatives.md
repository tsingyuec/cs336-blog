# Lecture 4: Attention Alternatives

## 本讲要解决的核心问题（SCQA）

**背景**：上一讲讲的是"基础 Transformer"——如何调整标准 Transformer 的各个部件来构建现代语言模型。这一讲进入更进阶的架构话题，主题是"在常规 Transformer 之上的新进展"。它要解决一个非常现实的需求：**大家都需要更长的上下文（context）**——把大量内容塞进上下文让模型拥有更多知识，或者让模型作为智能体（agent）处理很多信息。

**冲突**：看一张图就知道问题所在——横轴是不同模型、纵轴是上下文窗口大小（对数尺度），顶级模型厂商在竞相提供越来越大的上下文。可是成本怎么办？答案很残酷：**注意力是二次方的**。在序列较短时，网络的 feedforward（前馈）部分开销更大、且随长度线性增长；但注意力是所有位置之间的 all-to-all 连接，复杂度是 **O(N²)**。随着序列变长，**注意力会迅速超过 feedforward 成为主要开销**。[【跳转到 00:58】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=58)

![上下文窗口在各大模型间竞相增长；右图显示随序列变长，二次的注意力开销迅速超过线性增长的前馈](assets/p04/00083.jpg)

**疑问**：如果我们想处理十万、甚至上百万 token 的上下文，有没有办法让计算量随序列长度变成**线性依赖**？即便做不到完全线性，又有没有办法在不牺牲太多性能的前提下大幅降低成本？另外，Transformer 的另一半——MLP 层——有没有更高效的实现方式？

**回答（中心思想）**：**降低注意力成本有两条互补的路线。第一条是改造注意力模块本身：利用矩阵乘法的结合律，去掉 softmax 后把 QKᵀV 重新结合成 Q(KᵀV)，从而把对序列长度的依赖从二次降为线性（这就是线性注意力，它同时具备"密集并行"与"RNN 循环"两种形式）；在此基础上加门控得到 Mamba-2、再加投影擦除得到 Gated DeltaNet，最终以"线性层 + 少量全注意力层"的混合架构落地。第二条路线是改造 MLP：用混合专家（MoE）的稀疏路由，在 FLOPs 不变的前提下把参数量放大数倍。** 好消息是，这两条路线如今都已在大规模生产环境中得到验证。[【跳转到 04:01】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=241)

![本讲标题页：注意力替代方案与混合专家（Lecture 4，Tatsu 主讲）](assets/p04/00035.jpg)

注意：**常数因子其实至关重要**。受过传统理论训练的人容易只盯着 O 记号（线性还是二次），但对上下文与注意力成本影响最大的进展之一，恰恰是常数因子层面的系统改进——FlashAttention（详见之后的系统课程）。它把注意力运算重组成对系统更友好的形式、最小化内存搬运，能带来"真正惊人"的性能提升：原生 PyTorch 在短序列上大约每秒 30~40 TFLOPs，而 FlashAttention 能让性能翻倍，甚至在原生实现已经"塞不进内存"时仍能继续跑。[【跳转到 02:53】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=173)

但要处理几十万、上百万 token，这些技巧就不够用了——我们需要在长上下文能力上获得更激进、更大幅度的提升。这就引出了"有没有办法对序列长度实现线性时间复杂度"的问题。[【跳转到 03:43】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=223)

## 一、线性注意力的全部起点，是矩阵乘法的结合律

**一句话结论**：注意力之所以是二次的，是因为先算 QKᵀ 得到 N×N 的大矩阵；只要允许重新结合括号、先算 KᵀV，计算量就只依赖头维度而非序列长度。

### 1.1 注意力为什么是二次的
要理解所有"线性时间注意力"方案，只需先抓住一个核心思想：**乘法的结合律**。回顾注意力的紧凑写法——由 Q、K、V 组成：

1. 先让 Q 和 K 做 all-to-all 交互：计算 **QKᵀ**。这个矩阵的大小是 **N×N**，正是二次复杂度的来源（N 动辄数百万，也就是上下文长度）。
2. 用 softmax 对这一行做归一化。
3. 再和值 V 相乘，得到注意力输出。

### 1.2 结合律重排：先算 KᵀV，复杂度不再依赖序列长度
现在，先暂时"忘掉"softmax、把那一行去掉。**如果没有 softmax，我们就可以改变这个操作的复杂度。** 原本要做 QKᵀ 再乘 V，现在改成右结合——**先算 Kᵀ 与 V 相乘，再与 Q 相乘**。经过这种"重排序（括号移动）"后，二次的部分就消失了：我们不再需要 N² 项，取而代之的是依赖维度 **D、头维度 d_k 和 V 的 d_v**。理论上这些维度可以很大，但它们通常只在几千到几万的量级——**没人会在隐藏/头维度里设置百万级的坐标**。所以相比 N²，这一项的依赖关系"友好得多"。[【跳转到 04:26】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=266) · [【跳转到 05:16】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=316)

![利用结合律重排括号：从二次的（QKᵀ)V 变为线性的 Q(KᵀV)](assets/p04/00316.jpg)

### 1.3 有损与无损的边界
课堂问答特别澄清了一个易混点：从 softmax 注意力到线性形式的这一步是**有损的**（我们丢掉了 softmax）；但从"线性形式"到下面要讲的"循环形式"的等价性是**精确无损的**。这很关键——它意味着"线性化"的代价只发生一次。[【跳转到 17:07】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1027)

## 二、线性注意力有"双重身份"——训练时用并行形式，推理时用 RNN 形式

**一句话结论**：KᵀV 可以写成一种 RNN 式的增量更新形式；于是同一套参数既能用密集并行矩阵乘法训练，又能用固定大小的状态做推理，兼得两者之长。

### 2.1 KᵀV 的 RNN 形式
重排之后，右侧那个矩阵乘法（令 **S = KᵀV**）看起来就像一个 **RNN**：不必写成"密集形式"，而是可以在从左到右遍历上下文时**增量地**书写——把 K 和 V 相乘、更新这个状态 S、累加到之前的状态上，再与 Q 相乘得到输出。数学家会说：这种"密集形式"与"RNN 形式"在某种意义上是**等价的**。[【跳转到 06:06】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=366)

![线性注意力的 RNN 形式：状态 S 从左到右增量更新](assets/p04/00391.jpg)

### 2.2 训练用并行、推理用串行
这样做的妙处在于：

- **RNN 的优点在推理**：你有一个大小**固定**的状态 S，不断把它向前传递。推理时代价与序列长度无关，非常理想。
- **线性注意力的优点在训练**：你可以用"密集（并行）形式"，它天生并行，对训练非常有利。

所以你可以**同时采用两种形式**：训练走并行、推理走串行，兼得两者之长。[【跳转到 06:56】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=416)

### 2.3 现实中的混合架构
这种"基础线性注意力"已经足够实用。例如某大型中文开源模型采用了 **"7 比 1 的混合方案"**——7 个线性注意力层配 1 个完整的 softmax 注意力层——整体性能很有竞争力，而且对上下文长度的依赖大部分是准线性的。它并非完全线性（因为还穿插着 softmax 层），但这种依赖要温和得多。[【跳转到 07:46】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=466)

**一个至今仍然重要的经验事实**：目前还没有人在大规模上真正验证"完全线性时间注意力"。本讲要讲的所有落地模型，都是**混合架构**——即线性层与不时穿插的二次注意力层搭配使用。[【跳转到 08:50】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=530)

## 三、给线性注意力加门控得到 Mamba-2，再加"投影擦除"得到 Gated DeltaNet

**一句话结论**：Mamba-2 本质上是在线性注意力上加入一个输入相关的衰减门 γ，让状态能"遗忘"；Gated DeltaNet 再加第二个门 β 去投影擦除旧信息，两者都保持了并行/串行对偶性。

### 3.1 Mamba-2：给线性注意力加一道衰减门
**Mamba-2** 来自 Albert Gu 及其合作者提出的**状态空间模型（SSM）** 系列。虽然他们最初从状态空间理论推导，但审视其操作机制会发现：它实际上可以视为**线性注意力的一种简单扩展**。[【跳转到 09:13】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=553)

它的核心观察是：线性注意力最大的问题是"它总是把状态一直往后传，从不遗忘"。而从早期 LSTM 时代我们就知道，关键在于**知道什么时候该把信息往后传、什么时候该把它忘掉**。于是 Mamba-2 加入一个**门控 γ（衰减因子）**：γ_t 本身没有状态，只取决于当前输入 x_t，用来"调节"有多少状态信息被传递到未来。因为 γ 完全不依赖状态，计算非常简单。它同样保留了"双重性"——既可作为大型稠密矩阵乘法，也可在推理时用循环形式。[【跳转到 09:38】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=578)

![Mamba-2：在线性注意力状态更新上加入输入相关的衰减门 γ](assets/p04/00603.jpg)

### 3.2 门控只依赖输入，就能保持并行/串行对偶性
**一个可推广的经验法则**：只要你对 RNN 中的各项做门控，且门控只包含"依赖输入的项"、不依赖状态，那么你就能在"并行操作（训练）"和"串行操作（推理）"之间保持相当好的对偶关系。[【跳转到 11:25】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=685)

### 3.3 Gated DeltaNet：第二个门与投影擦除
**Gated DeltaNet** 则借用了这个思路，并加入**第二个门控 β_t**：β_t 可以看作一个"是否写入状态"的门——如果 β 为零，就意味着"不要采用当前信息、不要把它加进状态"。这让人想起 LSTM：通过门控决定"是否遗忘""是否从当前时间步输入信息"，原则非常相似。[【跳转到 12:15】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=735) · [【跳转到 13:05】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=785)

更妙的是 Gated DeltaNet 的**更新方向**：它不只是"写入新信息"，还要**擦除之前已经写入的当前 key 方向上的信息**。数学上，更新形式里的 `(I − β_t k_t k_tᵀ)` 就是一个**投影器**——把状态中沿 k_t 方向的内容投影掉，再写入新的 k_t v_t。直观理解：为当前 key 写入信息时，先把它旧的内容擦除。[【跳转到 13:30】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=810)

![Gated DeltaNet 的更新：用 (I − β_t k_t k_tᵀ) 投影擦除当前 key 方向上的旧信息](assets/p04/00835.jpg)

### 3.4 一个被反复重新发明的方法
有意思的是，Gated DeltaNet 在历史上被**反复重新发明**过：当人们试图解决某些"在线最小二乘"问题时，就会自然出现这种投影器；在"快速权重编程（fast weight programmers）"或"测试时训练（test-time training）"领域，研究人员基于完全不同的设计原则，最终得出了几乎相同的解决方案。[【跳转到 14:20】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=860)

## 四、混合架构已成为主流——用少量全注意力层"兜底"，性能几乎无损

**一句话结论**：Qwen-Next 等先进开源模型正式采用"门控 DeltaNet + 全注意力"的 3:1 混合架构，随上下文变长解码吞吐远高于纯 Transformer，而性能几乎没有损失；但一旦线性层占比过高，性能会明显下降。

### 4.1 Qwen-Next 的 3:1 混合架构
**Qwen-Next（以及其后续版本）** 是目前最优秀的开源模型之一，正式采用了**"三比一的门控 DeltaNet-注意力混合架构"**。它的推理特性出色：随着上下文长度不断增加，其解码吞吐量远高于上一代纯 Transformer 模型；而从性能对比看，这种混合架构**似乎对性能几乎没有任何损害**。[【跳转到 15:04】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=904)

![Qwen-Next 的混合架构：随上下文变长，解码吞吐远高于纯 Transformer，性能几乎无损](assets/p04/00904.jpg)

### 4.2 混合比例的对照研究
目前关于"混合架构性能"的高质量对照研究还不多。有一项研究比较了 Mamba-2、Gated DeltaNet 等架构在**不同混合层数**下的表现。核心发现是：

- 把非全注意力的层统称为 **RNN 层**，从左往右 RNN 层越来越多，性能随之下降。
- 对表现最好的架构（如 Gated DeltaNet 及其变体），在**低 RNN 占比**时**基本没有性能损失**；
- 但一旦超过某个**临界点**，就会出现更明显的性能下降（本例中体现在长上下文性能上）；
- **完全切换到纯 RNN 时，性能下降会变得非常明显**——所有架构都是如此。

[【跳转到 16:01】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=961)

需要客观看待的是：像"单针检索（needle-in-a-haystack）"这类任务，很多长上下文架构本身就**明确针对它做了优化**；但换成 QA 等更通用的任务，规律依然清晰——**随混合比例升高，性能呈稳定且明确的下降趋势**。[【跳转到 16:26】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=986)

### 4.3 为什么纯线性会掉性能
**为什么纯线性会掉性能？** 讲者用"缺点即表达能力"来解释：softmax 注意力里的 all-to-all 连接非常强大、也很好训练。状态空间模型虽然与 LSTM 相似（也有类似的表达能力短板），但如今因为有了"清晰的二重性"（可在 RNN 形式与密集矩阵乘法形式之间切换）而重新流行——这种权衡"改善了"，但并未消失。核心是**状态规模与上下文长度的比例**：状态越小，就越难把大上下文的所有信息压缩进去。**没有免费的午餐**。[【跳转到 27:22】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1642)

## 五、DeepSeek 稀疏注意力（DSA）——用轻量索引器先"选"，再对小子集做全注意力

**一句话结论**：DSA 不改变二次复杂度，而是先用一个轻量索引器对全部 token 打分、挑出 top-k 子集，只对这个小子集做全注意力，从而用系统层面的技巧大幅降低实际成本。

### 5.1 DSA 的前向机制：先选后算
除了"线性化"，还有另一条完全不同的思路：**稀疏注意力**。DeepSeek 在某版本中引入了 **DSA（DeepSeek Sparse Attention）**。它的做法是：**不**对所有 token 计算注意力，而是先用一个**轻量级索引器（lightning indexer）**，从大量 token 中筛选出一个**远小于完整序列的子集**，再对这个小子集做全注意力计算。[【跳转到 18:21】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1101)

前向传播的机制其实很简单：

1. 照常生成 Q 和 K，把它们送入索引器；
2. 索引器先算 Q 和 K 的内积、利用前面 token 的信息生成权重，给出每个位置的近似重要性分数；
3. 对这些分数做 **Top-k 筛选**，把"若干排名靠前的位置"纳入注意力计算；
4. 再照常做注意力计算（输出键值对）。

因为选择性非常稀疏、索引器又足够轻量，执行全注意力的部分就能在一个**很小的子集**上完成。[【跳转到 19:11】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1151)

![DeepSeek 稀疏注意力：轻量索引器对全部位置打分，经 Top-k 选出一个小子集再做全注意力](assets/p04/01151.jpg)

### 5.2 不必从零训练索引器
**一个巧妙的工程点**：你其实不必"从零"训练这个索引器。由于我们本来就很难从零训练长上下文模型（先训短上下文、再做长上下文扩展阶段），DeepSeek 的做法是"**先训练普通 Transformer，再在长上下文扩展阶段把索引器嵌入进去**"，让模型在这个阶段适应它。这样实际计算成本相当低。[【跳转到 19:36】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1176)

### 5.3 复杂度澄清：DSA 并不是线性的
**关于复杂度的重要澄清（课堂问答）**：DSA **不是线性的**——索引器仍需处理完整的 **O(N²)** 内积计算，因为它必须遍历所有内容才知道该选什么，这是纯粹的暴力计算。后续全注意力那部分也是 O(N²)。**它取得优势靠的是系统层面的技巧**：让索引器的维度非常低、让投影矩阵非常小，从而把常数因子压到极小。[【跳转到 22:09】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1329) · [【跳转到 23:03】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1383)

值得一提：DeepSeek 还展示了 DSA 在"预填充"和"解码"两个阶段的有利扩展性；也有其他优秀开源模型采用了类似方法，并给出了"带预热 DSA / 纯 DSA / 完全不用 DSA"的消融实验，说明只要进行完整的 DSA 训练，损失很小，即便在长上下文检索这种 RNN 架构难处理的任务上，表现也接近完整注意力。[【跳转到 20:26】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1226) · [【跳转到 21:16】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1276)

### 5.4 Top-k 是之后 MoE 内容的伏笔
讲者还点出一个更普适的规律：**"Top-k 选择"将成为接下来 MoE 内容的核心**——它会在很多地方以"重复模式"出现，学会识别它很有好处。[【跳转到 21:56】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1316)

## 六、MoE 的本质，是用"稀疏性"换来"参数多、FLOPs 不变"

**一句话结论**：MoE 只是"更高效的 MLP"——把一个大的前馈网络拆成多个专家，每次只激活极少数，从而在不增加单次前向 FLOPs 的前提下把参数量放大数倍；而"更多参数通常有益"正是它的价值来源。

### 6.1 MoE 只是更高效的 MLP
讲者说，Mixture of Experts 从概念上并没有真正改变复杂度格局，一种理解方式是：**它只是"更高效的 MLP"**。但它值得展开，原因有二：其一，如今大家都在做 MoE、都在部署 MoE，要深入理解语言模型就必须懂它；其二，MoE 里有非常有意思的机制性组件，你会发现很多"原语"在其他地方也会反复出现。[【跳转到 28:04】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1684)

**什么是 MoE？** 它其实就是"MLP 的替代品"。左边是 Transformer 里通常的 MLP（归一化后接前馈网络 FFN），大量密集信息处理就发生在这里。现在换个思路：把那个大的 FFN 拆成几个**小的 FFN**（例如 4 个），并且让每个专家保持和原来一个 FFN 一样大，再通过一个**路由器（router）**决定"针对每个输入 token，该选择哪个前馈网络"。[【跳转到 28:49】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1729)

![MoE 的基本结构：把单个大 FFN 换成多个专家，路由器为每个 token 选择激活哪个](assets/p04/01754.jpg)

### 6.2 参数放大数倍，而单次 FLOPs 不变
于是：**参数量变成原来的数倍**（就 FFN 部分而言），但**任何一次前向或反向传播中，只需承担一个（或 K 个）FFN 的计算成本**。这呼应了原始 MoE 论文"以参数为中心"的动机——如果你相信"参数越多越好"，又不想为更多参数付出计算代价，就需要这种结构。所以对 MoE 的正确心智模型是：**在不影响总 FLOPs 的前提下增加参数量**。[【跳转到 30:04】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1804)

### 6.3 它为什么流行：更多参数通常有益
**它为什么流行？** 经验事实是：在总计算不变的前提下，只增加"稀疏参数"的数量，模型性能通常都会变得更好。Switch Transformer 等论文显示：**随着专家数量增加（激活参数量保持不变），语言建模验证损失持续下降**；在训练预算相同时使用更多专家，性能也会提升。也就是说，无论训练还是推理，MoE 都能"轻松取胜"。[【跳转到 30:54】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1854)

![Switch Transformer 结论：专家数量越多，验证损失持续下降](assets/p04/01854.jpg)

实证支持反复出现：某开源 MoE 研究也观察到，"训练一个 MoE 模型比稠密模型大约快 2 倍"；而看所有已发布的 MoE，就"激活参数量"而言，它们比对应的稠密模型强得多——这非常关键，因为你最终要按推理时的有效 FLOPs 来算成本。早期某些 MoE 模型问世时确实带来了深刻转变："我们的激活参数少得多，表现却一样好甚至更好。"[【跳转到 31:44】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1904) · [【跳转到 32:34】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1954)

### 6.4 对系统的额外价值：专家并行
**对系统的额外价值**：MoE 提供了"另一个并行化维度"。语言模型非常庞大，训练和推理都无法装入单个设备，需要多种模型切分方式；而 **MoE 里的每个专家天然就是"分块"的**——你可以把它们放在不同设备上，把激活值路由（route）到相应设备。这种 **专家并行（Expert Parallel）** 为系统优化提供了额外空间。[【跳转到 32:59】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1979)

## 七、MoE 的路由器设计——token 选择是主流，共享专家 + 细粒度专家是最佳实践

**一句话结论**：路由方式分"token 选专家"与"专家选 token"，前者更稳更常用；DeepSeek 提出的"细粒度专家 + 共享专家"设计经消融验证有效，已成为 MoE 的事实标准。

### 7.1 token 选择专家 vs 专家选择 token
设计 MoE 时可以从三个维度调整：**路由函数、专家规模、训练方法**。先看路由。因为我们不希望激活全部专家，所以总要做 **top-k 选择**，而选择方式大致有两种：

- **token 选择专家**：由每个 token 挑选自己偏好的 K 个专家；
- **专家选择 token**：由每个专家挑选偏好的 token。

研究显示：**token 选择通常能获得更低的验证损失和更高的下游基准分数**，也更容易跑通、更稳定，已基本成为"所有现代模型的标准做法"。[【跳转到 40:20】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=2420) · [【跳转到 40:53】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=2453)

### 7.2 最常见的路由器与 top-k 公式
**最常见的路由器**非常简单：用一个小型线性投影，计算每个专家向量（可看作原型/质心）与输入的内积，取分数最高的 K 个。这就是经典 Switch Transformer 用的方案。其他可选做法包括：基于哈希的路由（常见基线，但实际部署少用）、用**强化学习**学习路由策略（早期工作用过，但会引入大量开销，不常见）、以及"求解线性指派问题"求全局最优分配（有道理但代价太高，未在大规模出现）。实践中人们最终选择的是"**一套不错的启发式方法 + 经典 top-k**"。[【跳转到 41:30】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=2490) · [【跳转到 43:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=2615)

top-k 路由的公式形式很直观：输入 x 经过一个投影得到路由分数，对分数做 softmax，再挑出得分最高的 K 个专家，用它们对应的权重做**加权的 top-k**（而非绝对硬选择），最后把结果加回残差项。[【跳转到 44:05】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=2645)

![top-k 路由：输入经投影得到分数，softmax 后取 top-k 专家加权求和再并入残差](assets/p04/02645.jpg)

### 7.3 DeepSeek 的共享专家机制
**DeepSeek 的贡献**：DeepSeek-MoE 首创了如今被广泛采用的**共享专家（shared expert）机制**。想法很直观：经典 top-k 路由器中有 N 个大的不同专家、从中选 K 个；但有些"通用处理"步骤你希望**对所有 token 都应用**。于是 DeepSeek 把专家**拆成更小、更细粒度的单元**，并将其中一部分设为**始终启用的共享专家**——它们绕过路由器、始终处理输入，结果再汇回输出端。这样可以**把通用处理卸载到共享专家上，让其余专家更专门化**。[【跳转到 45:06】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=2706)

![DeepSeek 的共享专家 + 细粒度专家：一部分专家始终启用、绕过路由器](assets/p04/02731.jpg)

### 7.4 消融证据与事实标准
**消融实验的证据**：对比"0 个共享专家 + 大专家"与"细粒度专家 + 共享专家"，两项改动都带来明显性能提升，在某些任务上共享专家效果尤其明显。不过，某西方开源 MoE 的受控研究则得出"共享专家作用并不显著"的结论，但他们也证明"使用大量细粒度专家是有益的"。二者在共享专家上略有分歧。[【跳转到 46:38】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=2798)

无论如何，DeepSeek 的这套设计（细粒度 + 共享专家）已经像"LLaMA 之于稠密 Transformer"一样，成为 MoE 侧的**标准设计**，被许多现代开源模型广泛采用，是"经过充分实战检验的设计"。[【跳转到 47:21】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=2841)

**课堂问答：共享专家与并行化**。共享专家不会带来并行化的节省（每次激活都必须经过它），但你可以**复制（replicate）**共享专家——本质上是用更多内存换取更低的通信成本。[【跳转到 48:21】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=2901)

## 八、MoE 训练的核心难题是负载均衡——否则会发生"专家坍缩"

**一句话结论**：稀疏门控不可微、又看不到未被选中的专家，靠"启发式 + 辅助负载均衡损失"才训得动；若去掉均衡损失，几乎全部 token 会涌向极少数专家，大量参数被浪费。

### 8.1 为什么难：门控不可微、又看不到替代专家
MoE 训练棘手，是因为几个根本矛盾：

- 为了效率，训练时**不能激活所有专家**（否则要为所有专家支付全部 FLOPs，而专家数通常非常多）；
- 一旦引入稀疏性，**门控决策就不可微**了；
- 而且你**看不到**那些本可以选择的替代专家。

这让问题带有"强化学习中的多臂老虎机"色彩。[【跳转到 48:43】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=2923) · [【跳转到 35:12】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=2112)

### 8.2 三种解法
有三种解法：用强化学习优化门控策略（有效果，但梯度方差大、不常见）；用随机扰动打破平局、增加探索（早期做法，后来消融显示**去掉这些随机技巧反而有助于训练稳定性**）；以及实践中真正被采用的——**一大堆启发式规则**，来处理"门控稀疏"并平衡各专家负载。[【跳转到 49:08】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=2948)

### 8.3 不做均衡的后果：专家坍缩
**如果不做均衡会怎样？** 直接跑常规梯度下降，会出现一种"越用越强"的正反馈：路由器先选 top-k 专家，其中最强的那个获得更多信号、权重被调高，于是被选中频率更高，最终"几乎包揽所有工作"。这就是**专家坍缩（expert collapse）/ 专家饥饿（expert starvation）**，是一个非常现实的问题。[【跳转到 52:28】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=3148)

### 8.4 辅助损失及其直觉
**解法：辅助损失（auxiliary / balancing loss）**。在总建模损失之外再加一项，让流向不同专家的 token 分布更均衡。Switch Transformer 采用的方法：令 **F_i** 为"被分发给专家 i 的 token 比例"，**p_i** 为"路由分配给该专家的概率质量（更平滑的版本）"，让两者内积尽可能小。讲者说这个式子不太能从第一性原理推出，**理解它最简单的方法是求导**：对 p_i 求导得到 F_i，所以它相当于"梯度空间中的一种惩罚"——某个专家获得的 token 越多，其概率质量就被按比例压低。[【跳转到 53:18】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=3198)

![Switch Transformer 的负载均衡损失：F_i（token 比例）与 p_i（概率质量）的内积，用于均衡各专家负载](assets/p04/03198.jpg)

**去掉均衡损失的后果是灾难性的**。某开源 MoE 的消融实验显示：保留均衡损失时是正常的收敛曲线；去掉后损失显著上升。更有说服力的是专家利用率的可视化——**没有负载均衡时，几乎所有 token 都涌向两个专家**（图中黄色和粉色），其余专家在整个训练过程中几乎完全没发挥作用，等于浪费了大量参数；而加上均衡损失后，所有专家都被利用起来。[【跳转到 56:13】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=3373)

![去掉负载均衡损失后，几乎所有 token 只流向两个专家，其余专家被浪费](assets/p04/03398.jpg)

这一发现相当令人意外：你有一个**本质上不可微的操作**（top-k 选择）、一个相当复杂的损失对象，但**只需加上均衡损失让负载均匀一些，其余部分就当梯度可以直接传递**，模型就能训练得非常好。讲者总结其中关键是一种"正反馈动态"与"负载均衡"的相互抵消。[【跳转到 57:53】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=3473)

## 九、MoE 的系统与稳定性问题——专家并行、通信、非确定性、z-loss 与微调过拟合

**一句话结论**：MoE 在系统层面既有额外并行维度的好处，也有通信、非确定性、微调过拟合等独特挑战；业界用结构化稀疏、投影压缩、无丢弃架构、z-loss 等手段逐一应对，并发明了 upcycling 来"白捡"性能。

### 9.1 专家并行、通信与结构化稀疏
**并行与通信**：每一种标准并行技术都有极限（数据并行受批次大小上限限制，模型并行受天然切分点限制），而**专家并行多提供了一个并行维度**。许多底层实现还能利用 GPU 内置的**稀疏矩阵乘法**：与其做许多小矩阵乘法，不如利用稀疏性——用**块对角矩阵**乃至更复杂的**结构化稀疏**形式，这些都"硬件原生支持"，能以极快的方式完成专家与输入的计算。于是 MoE 的发展出现了一种**硬件架构协同设计**的趋势。[【跳转到 60:12】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=3612) · [【跳转到 61:08】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=3668)

### 9.2 用投影降维压缩通信
**降低通信开销的技巧**：专家并行必须在设备间**传输激活值**（告知 token 属于哪个专家、把它传过去），这带来显著通信开销。一种新方案是：**让共享专家保持较大隐藏维度（无需通信），而让需要传输的被路由专家使用更小的低维向量**。做法是先把残差流投影降维，再执行 all-to-all 通信，接收后再升维——相当于"只传输降维后的信号"，从而显著节省通信开销。[【跳转到 61:31】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=3691) · [【跳转到 61:56】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=3716)

![用投影降维压缩通信：共享专家保持大维度，被路由专家发送降维后的信号](assets/p04/03691.jpg)

### 9.3 非确定性与无丢弃架构
**非确定性（nondeterminism）**：如果朴素地实现 MoE 推理，某些热门专家会积压超长 token 队列，早期基础设施常见的做法是**静默丢弃**多余 token，于是出现"其他用户的查询命中同一专家时，你的结果反而可能变差"这种奇怪现象。如今**无丢弃（no-drop）架构**已经解决了大部分这类问题，主流开源 MoE 推理框架都不再有这个问题。[【跳转到 62:21】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=3741)

### 9.4 稳定性：z-loss 与高精度路由
**稳定性**：上一讲已经说过"指数运算是危险的、除法也是危险的"，而 softmax 正是稳定性问题的危险区域——**MoE 的路由机制里又引入了一个 softmax**。应对办法是：在更敏感的部分（尤其路由器）使用更高精度（如 FP32），并加入 **z-loss** 来控制 softmax 稳定性问题。消融实验清楚显示，在路由器上使用 z-loss 相当有帮助。[【跳转到 63:21】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=3801) · [【跳转到 64:11】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=3851)

### 9.5 微调过拟合与 upcycling
**微调代价**：MoE 参数众多，**微调 experts 时会出现严重的过拟合**——稠密模型的训练/验证损失相当接近，而稀疏模型在下游任务微调时两者差距很大。常见对策是**只微调非 MoE 的部分**（attention 或非专家的 FFN 层）。当然也有"苦涩教训式"的版本：也许应该直接用海量样本，在微调阶段几乎完全重新训练 MoE。[【跳转到 64:27】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=3867)

**Upcycling（升级复用）**：想构建 MoE，可以直接采用一个**已训练好的稠密模型**并"实例化"一个 MoE——复制所有参数（包括 MLP）、生成大量 MLP 副本、再随机初始化一个路由器，然后继续训练。由于输入分配到不同 MLP 的过程带有随机性，专家会逐渐变得专门化。早期论文表明，相较于继续训练同一稠密模型，upcycling 能显著提升语言建模性能——像是"白捡"的性能提升。早期某中文小模型和 Qwen 的 MoE 都成功用了这一技巧。不过这一方法在过去一年没有那么流行了。[【跳转到 65:59】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=3959)

## 十、DeepSeek 的 MoE 演进——从"共享+细粒度专家"到 MLA、MTP 的标准范式

**一句话结论**：DeepSeek 的 MoE 论文很好地体现了"成功训练不仅关乎深度学习，也关乎系统性"；V1 立下共享专家+细粒度+辅助损失的范式，V2 放大规模并加入设备/通信平衡，V3 则演进到 MLA 与多 token 预测。

### 10.1 DeepSeek MoE V1/V2/V3 的演进
讲者特别推崇 DeepSeek 的论文，认为它们写得好、细节多，体现了对系统本身的重视：

- **DeepSeek MoE V1**：实际上已经是许多现代 MoE 的**原型**——共享专家 + 细粒度专家、标准 token 路由、辅助损失平衡。可以说是 MoE 的"标准范式"。
- **DeepSeek-V2**：基本是把 V1"放大"——两个共享专家、更多细粒度专家，并加入**设备级平衡组件**与**通信量平衡组件**；值得注意的是，它不仅有"专家间平衡"，还有"设备间平衡"——因为专家分布在不同设备上，你希望各设备都接近满负荷运行，于是引入次要的设备平衡损失（数学形式相同，只是针对设备负载）。这正是"DeepSeek-V2 是'重视系统'这一理念的体现"。
- **DeepSeek-V3**：保留共享专家 + 细粒度专家，但改用"无辅助损失（或每序列辅助 + 偏置在线调整）"的方式来平衡专家，并采用 sigmoid 等不同的加权方式。它仍需要一些辅助损失来避免极端不平衡，但已能摒弃部分"不够优雅"的辅助损失。

### 10.2 MLA：压缩 KV 缓存
**多头潜在注意力（MLA，Multi-head Latent Attention）**：DeepSeek 不直接生成 Q、K、V，而是先把隐藏输入压缩成**低维的共享潜在状态 C**，再基于 C 投影生成 Q、K、V。这样在解码阶段**无需缓存所有的 K 和 V**，只需存储维度更低的 C，从而获得可观的 KV 缓存与计算节省。这就是它叫"潜在注意力"的原因。唯一需要小心的是与 **RoPE** 的交互：位置信息与内容信息纠缠在 KV 里，而位置信息不适合压缩，所以实践中会保留一些专门编码位置信息的非潜在维度、不做压缩。[【跳转到 69:19】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=4159)

### 10.3 MTP 与未来方向
**多 token 预测（MTP，Multi-Token Prediction）**：与其只预测下一个 token，不如**一次性预测多个**。这在统计上是有道理的（可能让你对未来预测得更准），从系统角度看更是内置了一个**投机解码器（speculative decoder）**，可用于加速模型解码。[【跳转到 70:34】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=4234)

讲者在课堂问答中提了对未来的判断：不同技巧会被"全都用上"，架构通过整合各种成功配方变得越来越复杂；而更高层面的方向，是**利用后训练让模型自己管理上下文**（压缩、检索等机制从"最外层附加"走向"整合进模型"）。[【跳转到 25:23】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=4&t=1523)

## 小结

- **长上下文的成本瓶颈在注意力**：feedforward 随长度线性增长，而注意力是 all-to-all 的 O(N²)，序列越长越主导开销；FlashAttention 是常数因子层面的巨大改进，但不解决二次增长。
- **结合律是线性注意力的起点**：去掉 softmax 后，`(QKᵀ)V` 可重排为 `Q(KᵀV)`，计算量改由头维度决定而非序列长度；softmax→线性的这一步有损，线性→RNN 的等价则无损。
- **双重形式**：线性注意力既是密集并行矩阵乘法（适合训练），又是固定状态的 RNN 循环（适合推理），可兼得两者之长。
- **门控演进**：Mamba-2 加入输入相关的衰减门 γ 让状态能遗忘；Gated DeltaNet 再加门 β 并用投影器擦除旧信息；门控只依赖输入时，并行/串行对偶性得以保持。
- **混合架构是现实答案**：Qwen-Next 用 3:1 门控 DeltaNet + 全注意力、某中文大模型用 7:1；低 RNN 占比时性能近乎无损，纯线性则明显下降——状态容量的权衡无法回避。
- **DSA 是另一条路**：用轻量索引器对全部 token 打分、Top-k 选出子集后只对子集做全注意力；不是线性的，但靠极小的常数因子取胜，且可在长上下文扩展阶段插入。
- **MoE = 更高效的 MLP**：稀疏路由让参数量放大数倍而 FLOPs 不变；"更多参数通常有益"是它的价值来源，也提供了专家并行这一额外系统维度。
- **MoE 设计要点**：token 选择专家是主流；共享专家 + 细粒度专家是 DeepSeek 立下的事实标准；辅助负载均衡损失不可或缺，否则会发生专家坍缩、浪费大量参数。
- **MoE 的系统与训练挑战**：通信、非确定性、softmax 稳定性（z-loss、FP32 路由）、微调过拟合、以及可"白捡"性能的 upcycling。
- **DeepSeek 范式**：V1 原型 → V2 放大并加设备/通信平衡 → V3 演进，配合 MLA 压缩 KV 缓存与 MTP 多 token 预测。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| 线性时间注意力 | 通过去掉 softmax 并重排乘法顺序，使计算量不随序列长度二次增长的一类注意力。 |
| 结合律重排 | 把 `(QKᵀ)V` 改写为 `Q(KᵀV)`，使中间矩阵由 N×N 变为头维度大小。 |
| 双重形式 | 线性注意力同时具备"密集并行（训练用）"与"循环串行（推理用）"两种等价写法。 |
| 状态空间模型（SSM） | 以固定状态递归处理序列的模型族，Mamba 系列属之；机制上可看作线性注意力的扩展。 |
| Mamba-2 | 在线性注意力状态更新上加入输入相关衰减门 γ 的 SSM。 |
| Gated DeltaNet | 在 Mamba-2 基础上再加门控 β，并用投影 `(I−β k kᵀ)` 擦除当前 key 方向的旧信息。 |
| 混合架构 | 把若干线性层与少量全 softmax 注意力层按比例组合（如 3:1、7:1）的长上下文架构。 |
| DeepSeek 稀疏注意力（DSA） | 用轻量索引器对全部位置打分、Top-k 选出子集后只对子集做全注意力；靠常数因子取胜。 |
| 闪电索引器（lightning indexer） | DSA 中负责给所有位置打重要性分数、供 Top-k 选择的轻量模块。 |
| 混合专家（MoE） | 用稀疏路由在 FLOPs 不变的前提下大幅增加参数量的 MLP 替代方案。 |
| 路由器（router） | 决定每个 token 被分发给哪些专家的模块，通常是一次内积加 softmax 的 top-k 选择。 |
| token 选择专家 | 由每个 token 挑选偏好的 K 个专家；比"专家选 token"更稳、更主流。 |
| 专家选择 token | 由每个专家挑选偏好的 token 的路由方式；存在成功模型但不如前者常用。 |
| 共享专家（shared expert） | 始终启用、绕过路由器的专家，用于承担通用处理，让其余专家更专门化。 |
| 细粒度专家 | 把专家拆成更小单元以获得更好性能与更细粒度路由的设计。 |
| 专家坍缩 / 专家饥饿 | 不加均衡时少数专家包揽几乎所有 token、其余专家闲置的现象。 |
| 负载均衡损失 | 迫使各专家接收的 token 分布更均匀的辅助损失（如 Switch 的 F_i·p_i）。 |
| 专家并行（Expert Parallel） | 把不同专家放到不同设备、并将激活值路由过去的并行方式。 |
| 结构化稀疏 | 硬件原生支持的稀疏矩阵形态（如块对角），可高效实现 MoE 的专家计算。 |
| 无丢弃架构（no-drop） | 不再静默丢弃超长专家队列 token 的推理架构，消除了相关的非确定性。 |
| z-loss | 用于稳定 softmax 的辅助损失，在 MoE 路由器上尤其有帮助。 |
| Upcycling（升级复用） | 用已训练好的稠密模型初始化出一个 MoE 再继续训练，从而"白捡"性能。 |
| MLA（多头潜在注意力） | 把 KV 压缩成低维潜在状态 C 再投影出 Q/K/V，只为 C 做 KV 缓存以省显存。 |
| MTP（多 token 预测） | 一次预测多个未来 token，兼具统计收益与内置投机解码的加速能力。 |
