# Lecture 14: Data

## 本讲要解决的核心问题（SCQA）

**背景（Situation）**：上一讲我们聊过数据"从哪来"：互联网上的服务（比如 GitHub、论坛、网站）先被 dump 或抓取下来，然后经过一轮处理才变成"已处理数据"。这一讲是数据系列的第二天，聚焦最后一公里——**数据处理流水线（data processing pipeline）**，也就是怎么把原始数据**转换（transformation）**成文本，怎么**过滤（filtering）**、**去重（deduplication）**，以及怎么把不同来源**配比（data mixing）**；最后简单聊聊**后训练数据**，特别是现在如何大量使用合成数据。([【跳转到 00:00】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=0)、[【跳转到 00:10】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=10))

**冲突（Complication）**：这件事远比看上去复杂。原始数据根本不是干净的文本——你从 Common Crawl 拿到的可能是**HTML**，可能是**PDF**，GitHub 上则是**目录结构**。就算转换成了文本，里面还混着镜像站点、fork 仓库、到处都是的许可证、只差一个逗号的模板文章，甚至某个防毒面具的产品描述在数据集里出现了 **6.1 万次**。更麻烦的是，去重不能靠两两比对（那是 O(n²)，在网页规模上根本跑不动）；而数据配比看似只是"给几个来源分权重"，却隐藏着一个致命的细节：**在小数据源上分配太多权重，会在你毫不知情的情况下把同一份数据反复训练几十遍，直接过拟合**。([【跳转到 17:49】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1069)、[【跳转到 19:25】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1165)、[【跳转到 37:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2255))

**疑问（Question）**：一条可靠的数据流水线到底由哪些环节组成？每个环节有哪些实用方法，背后又要提防哪些"规模相关的坑"？

**回答（A，结论先行）**：数据处理可以拆成四个环节，每个环节都有清晰的抽象与工具：

1. **转换**：把 HTML / PDF / 代码目录线性化成 token 序列，重头戏是 HTML→文本。这是**有损**过程，通常用**基于规则**的快工具（trafilatura、resiliparse、jusText、lynx）来做。
2. **过滤**：先定义"什么算好数据"（语言、质量、毒性），再用**生成式小模型（如 KenLM 的 5-gram）**或**轻量分类器（fastText 这类线性模型）**打分，按阈值保留。算力有限时过滤尤其关键——因为绝大多数人的算力都不足以"直接用全部数据训练"。
3. **去重**：精确去重靠**哈希分组**；近似去重靠 **Jaccard 相似度 + MinHash + 局部敏感哈希（LSH）**，把匹配从 O(n²) 压到线性时间。相关的**去污染（decontamination）**——保证测试集不泄漏进训练集——甚至更重要。
4. **配比**：要同时兼顾**质量、多样性**和**每个源的 epoch 数**；无原则的手调之外，有 **UniMax**（均匀采样 + epoch 硬上限）和**基于回归的混合（RegMix 等）**两条有理论依据的路线。最后，**后训练数据**高度任务相关，如今几乎全部由强模型合成生成。

贯穿全讲的一个洞见是：**数据的"最优处理策略"会随规模变化**——训练越久越能容忍低质量数据，过滤阈值、配比比例、去重强度都不是固定常数。([【跳转到 00:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=35)、[【跳转到 06:36】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=396)、[【跳转到 11:36】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=696)、[【跳转到 44:54】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2694))

## 一、数据流水线总览：转换、过滤、去重、配比四道工序

### 1.1 用一页伪代码看懂整条流水线

这一讲的核心，可以用一页伪代码概括。讲者把整条数据流水线写成几个"函数调用"：

```text
# Data pipeline
transformation()   # 原始数据不是文本，先转成文本
filtering()        # 定义"什么算好数据"，训练分类器做筛选
deduplication()    # 去掉完全重复与近似重复
data_mixing()      # 为不同来源分配权重

# Post-training data
post_training_data()
```

**为什么是这个顺序？** 因为每一步的输入都是上一步的输出：转换产出的文本里夹杂着垃圾（要过滤）；过滤后的文档里仍有大量重复（要去重）；最后剩下的高质量文档来自不同来源（要配比）。这条流水线的每一环都值得单独研究，本讲就是把它逐个拆开讲清楚。([【跳转到 00:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=35))

### 1.2 先建立一个预期：真实的数据工作更琐碎

需要建立一个整体预期：**真正的数据工作比课堂上呈现的要琐碎得多**。讲者在结尾坦言，很多数据工作"相当依赖具体领域，得盯着具体例子"才能做出高质量数据集，这堂课只能帮大家理清数据全貌，很难完全代表真实世界的数据工程。([【跳转到 57:18】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3438))

## 二、转换：把 HTML / PDF / 代码目录变成文本，本质是一个有损过程

### 2.1 第一步永远是理解"原始数据不是文本"

转换环节要处理的输入有三种典型形态：

- **HTML**：网上绝大多数内容的形式，也是重头戏；
- **PDF**：比如 arXiv 上的论文；
- **目录**：比如 GitHub 上的代码仓库。

它们都不是平坦的文本：HTML 是**层级结构**，PDF 有可视化的版面，代码目录有文件树。而语言模型最终要的是一串 **token 序列**，所以转换必须把这些结构**线性化**——这个过程天然是**有损**的。([【跳转到 00:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=35)、[【跳转到 01:25】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=85))

### 2.2 HTML→文本：删掉样板，抽出正文，但"什么算内容"界限模糊

HTML→文本的基本操作是**移除样板（boilerplate）**——页脚、页眉、菜单、导航栏、广告——然后提取页面主体内容。但立刻会碰到一个哲学问题：**"导航元素"到底算不算内容？** 一般做法是统统删掉，可有时部分导航元素恰好能帮助理解网页的整体布局。所以"哪些属于内容、哪些不属于"往往**界限模糊**，全靠经验拿捏。([【跳转到 01:00】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=60))

图片和表格更棘手。简单表格可以用 **Markdown** 渲染，但**嵌套表格**的挑战显著增加——你总得在某个环节妥协或近似处理。正因为这一步不需要太高的"智能"，而且要在海量网页上极快地跑，实践中最常用的是**基于规则的方法**，代表工具包括 **trafilatura、resiliparse、jusText、lynx** 等。不过不同工具的准确度并不一样：在扩展的 **DCLM 评测**里，讲者认为 **resiliparse 的效果比其他工具都要好**。当然，基于规则难免出错，数据里总有些瑕疵。([【跳转到 01:50】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=110)、[【跳转到 02:15】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=135))

![HTML 转换的要点：原始数据不是文本（HTML / PDF / 代码目录），HTML→文本要移除样板（navigation、ads 等）、抽取正文，且天然有损，常用 trafilatura、resiliparse、jusText、lynx 等基于规则的工具。](assets/p14/00085.jpg)

### 2.3 PDF：占比小但平均质量高，扫描件要用视觉语言模型做 OCR

PDF 值得单独一提。Hugging Face 发布过一个名为 **FinePDFs** 的 PDF 数据集。PDF 的麻烦在于：**不借助专门渲染器，你拿到的只是一堆"绘制指令"**——它记录的是"在某个绝对位置画一段文字"这种命令，并没有显式的语言结构（例如 `<p>` 这样的语义标签），阅读顺序也不能保证，版面必须靠几何位置去推断。([【跳转到 02:40】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=160)、[【跳转到 02:49】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=169))

Common Crawl 收录了大量 PDF，但有两个坑：

1. **很多 PDF 因文件过大被强行截断**，这就需要重新抓取；
2. **有些 PDF 其实只是扫描件**（本质是图片），这时必须用**视觉语言模型（VLM）做 OCR**，成本比处理纯文本高得多。

好在（或者说不好在）**PDF 在整个互联网里只占很小一部分**。但它**很有价值**：愿意专门制作 PDF，通常意味着内容经过精心整理，因此 **PDF 的平均质量高于 HTML**。代价是 HTML 里那些标签能提供的语义信息在 PDF 里丢失了，所以 PDF 过滤后往往需要**更多清洗**。([【跳转到 03:36】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=216)、[【跳转到 03:41】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=221))

## 三、过滤：先定义"好数据"，再训练一个小分类器去大海捞针

### 3.1 过滤的通用框架：给定目标数据 T 和原始数据 R，选出相似子集 T′

过滤看起来五花八门，但几乎所有方法都套用同一个基础模块：

> 给定一小部分高质量的**目标数据 T（target data）**，以及大量刚从转换步骤出来的**原始数据 R（raw data）**，目标是从 R 中挑出一个与 T 相似的子集 T′。

典型应用有三类：**语言识别**（英语 vs 其他语言）、**质量过滤**（高质量 vs 低质量，要像百科全书一样有深度，不要垃圾信息）、**毒性过滤**（无毒 vs 有毒）。([【跳转到 04:06】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=246)、[【跳转到 04:31】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=271))

![过滤的通用框架：在原始数据 R 中寻找与目标数据 T 相似的子集 T′；典型应用是语言识别、质量过滤、毒性过滤。](assets/p14/00296.jpg)

### 3.2 过滤算法的两条硬性要求：能泛化、且极快

对过滤算法有两条不可妥协的要求：

- **能泛化**：算法必须能从目标数据推广出去，T 与选出的 T′ **不能雷同**（否则就是把答案抄了一遍）；
- **极快**：因为要在**全互联网**上跑一遍，数据量可能高达 **10 万亿 token**，最终只保留**个位数百分比**的数据。([【跳转到 04:56】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=296)、[【跳转到 05:21】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=321))

### 3.3 两类分类器：生成式模型与轻量分类器

给定 R 和 T，基本思路是**先训练模型、得到打分函数，再按分数保留**。分类器分两类：

1. **生成式模型**：直接基于 T 估计分布，打分 `score(x) = p_T(x)`。为保持低成本，通常不训练大模型，而是用 **5-gram** 这类小语言模型，代表是 **KenLM**。
2. **简单分类器**：把属于 T 的样本标为正、从 R 中随机抽取的样本标为负，训练一个分类器；实践中常用 **fastText**，因为它快——本质是一个基于**词袋（bag of words）**的**线性分类器**。得到模型后对每个文档打分，按阈值保留（有时还带随机性，按分数做随机采样而不是硬阈值）。([【跳转到 05:46】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=346)、[【跳转到 06:11】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=371))

![过滤的通用做法：用生成式小模型（如 KenLM）或简单分类器（如 fastText）给文档打分，按阈值保留；至于要不要基于模型过滤，历史上存在分歧，如今使用已渐成常态。](assets/p14/00446.jpg)

### 3.4 一个立场之争：到底要不要做"基于模型的过滤"

这里有个值得了解的历史分歧：

- **一派刻意不用**基于模型的过滤，担心引入偏见，代表数据集有 **C4、Gopher、RefinedWeb、FineWeb、Dolma**；
- **另一派使用**，代表有 **GPT-3、LLaMA、DCLM**，如今这已经**成为常态**。

为什么会转向"用"？核心原因是**算力有限**。理论上有无限算力就可以直接用全部数据训练一个庞大模型，但现实中大多数人的算力都不够，**必须想清楚过滤策略，否则就是在低质量内容上白白浪费算力**。([【跳转到 06:36】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=396)、[【跳转到 07:01】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=421))

## 四、过滤实例：质量没有统一定义，最优阈值还会随规模变化

### 4.1 语言识别：用几个词就能分辨，Meta 的模型支持 176 种语言

**语言识别**目标很明确：给定一段文本，判断它属于哪种语言。这类任务相对简单——用一个小分类器看几个词，就能分辨出西班牙语还是日语。**Meta 训练过一套快速的文本语言识别模型**，支持 **176 种语言**，训练数据来自维基百科、**Tatoeba**（翻译网站）、**SETimes**（东南欧新闻）等多语言站点。落地时，**Dolma** 保留 `p(English) >= 0.5` 的文档。([【跳转到 07:26】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=446)、[【跳转到 07:51】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=471))

不过要留个心眼：文本里常有**语码转换（code-switching，一段话里混用多种语言）**和方言，细节上有点复杂，所以说它"已彻底解决"有些夸张——但它确实**不是训练语言模型的关键瓶颈**。

### 4.2 数学语料 OpenMathText：多条规则 + 生成式模型 + 分类器组合拳

**OpenMathText（Paster 等，2023）** 的目标是从 Common Crawl 里整理大规模数学文本。它**不是只训练单个分类器**，而是一套组合流程：

1. **基于规则**：检查文本是否包含 LaTeX 命令；
2. **生成式方法**：用 **KenLM** 在已知数学数据集 **ProofPile** 上训练，**保留困惑度低于 15000** 的文档；
3. **分类器**：训练一个 **fastText** 判断是否属于数学写作，**若是数学阈值 0.17、若不是数学阈值 0.8**。

最终得到约 **147 亿（14.7B）token**。结果显示：**这种更有针对性的数据筛选，能让模型在数学上表现更好**——用这批数据训练的 **1.4B 模型，优于在数据量大 20 倍的未过滤语料上训练的模型**。([【跳转到 08:16】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=496)、[【跳转到 09:06】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=546))

这引出全讲最重要的一句方法论：**质量过滤是一种工具，你可以自行定义"质量"**。质量并无统一定义——你把质量定义为数学能力，那收集数学数据就能提升数学表现。([【跳转到 09:06】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=546))

### 4.3 质量分类的三种典型做法：GPT-3、LLaMA、微软 phi

同一套框架可以套在很多著名模型上：

- **GPT-3**：**正样本**来自维基百科、WebText2、Books1、Books2 等，**负样本**从 Common Crawl 随机抽取，训练一个基于词特征的**线性分类器**，按分数随机保留文档。([【跳转到 09:31】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=571)、[【跳转到 09:56】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=596))
- **LLaMA / RedPajama**：正样本不是维基百科文章本身，而是**维基百科引用的页面**，思路类似。
- **微软 phi-1**：原始数据并非"预先切分好的 StackOverflow Python 子集"，而是**包含所有代码的完整数据集**。他们定义了一个 prompt 来判断样本是否具备**教育价值**，用 **GPT-4** 对 R 中 **10 万个样本**分类，被判定为正向的作为"目标"，再训练一个**更便宜的分类器**（他们用**随机森林**，fastText 也可以），最后用它去筛选剩余数据。效果显著优于直接用原始数据——能以更少的训练步数达到更高的性能。([【跳转到 10:21】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=621)、[【跳转到 10:46】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=646))

![过滤实例：从语言识别到数学语料（OpenMathText）再到 GPT-3 的正/负样本质量分类——同一套"定义目标数据 + 训练分类器 + 按分数筛选"的框架反复出现。](assets/p14/00596.jpg)

### 4.4 毒性过滤：复用同一套流程

**毒性过滤**原理相同：**Jigsaw Toxic Comments** 数据集（源自一个旨在改善网络交流环境的项目）就是这个思路的代表——明确定义正例和负例，训练分类器，然后用来过滤。Dolma 等数据集也用了它。([【跳转到 11:11】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=671))

### 4.5 不存在"最优阈值"：训练越久越能容忍低质量数据

到这里你已握有一套工具。但有个更微妙的细节：**所需数据类型取决于你计划训练多久（用多少 token）**。所以**并不存在所谓的最优阈值**——不能仅凭分类器给出 0.9 就断定它最优，这取决于具体场景。直观规律是：

> **训练周期长 → 可以容忍较低质量的数据；训练周期短 → 更希望数据质量高。**

讲者展示了一项由 **Michael Ryan** 完成的初步实验：对一个 **d512 模型（约 1.57 亿参数）**、用极小的数据池（**100 个 WARC 文件**，仅占 Common Crawl 极小一部分）训练，观察不同质量数据在重复遍历时的表现。

- 图中的每一条线代表模型完成一轮数据（一个 epoch）；由于数据总量有限，只能反复使用；
- 起初**高质量数据表现明显更好**；
- 但随着不断重复遍历，**低质量数据会逐渐追上来**；

## 五、去重（上）：为什么必须去重，以及用哈希做精确去重

### 5.1 重复无处不在：镜像站、fork、许可证、模板文章

数据里充满重复，分**完全重复**与**近似重复**两类，来源五花八门：

- **镜像站点**：本身就是为了复制内容，爬虫又分不清镜像与原站，于是抓到完全一致的副本；
- **fork 的代码仓库**：即使改过，通常也只涉及少数文件，**99% 的内容没变**；
- **服务条款与许可证**：比如 **MIT 许可证**在很多地方频繁出现（除非复制时打错字，否则完全一致）；
- **网站相同的页眉页脚**；
- **模板化文章**：来自 **LM1B** 基准的例子里，有些文章只差一个逗号，或是把"加拿大"替换成"美国"的同一模板，看起来就像广告；用这类只换了实体的变体训练模型，纯粹是在**浪费 GPU 算力**；
- **极端案例**：在对 **C4** 数据集的审计中，某款**防毒面具的产品描述出现了 6.1 万次**，讲者也说不出为什么。([【跳转到 15:43】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=943)、[【跳转到 16:54】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1014)、[【跳转到 16:59】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1019)、[【跳转到 17:24】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1044)、[【跳转到 17:49】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1069))

### 5.2 去重的三个动机，以及更重要的"去污染"

为什么要去重？三个理由：

1. **更高效地训练**：去重能在**不损失信息**的前提下缩减数据集规模——移除的只是重复内容；
2. **防止模型记忆训练数据**：如果大量受版权保护的内容被复制，模型可能直接记住，带来**隐私问题**；
3. **避免浪费计算资源**——讲者认为这是最主要的原因。

与去重密切相关、**甚至更重要的是去污染（decontamination）**：原理类似，但要确保**测试集的数据没有出现在训练集里**，否则评测结果就失真了。([【跳转到 18:10】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1090))

### 5.3 去重的设计空间：四个问题决定方案

动手之前先理清**设计空间**，也就是四个问题：

- **对什么去重？** 句子、段落，还是整篇文档；
- **怎么算匹配？** 要求完全一致，还是包含相同子串就算；做近重复时，共同部分占多大比例算匹配；
- **阈值定多少？**
- **找到重复后怎么处理？** 全删，还是只保留一份？([【跳转到 18:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1115)、[【跳转到 19:00】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1140))

这里有个核心的**算法难点**：去重本质上是**项目之间的两两比对**。过滤是"针对单个项目"处理，可以线性扫一遍；但去重不能采用 \(O(n^2)\) 的暴力两两比较，**必须用线性时间复杂度的算法**才能扩展到网页规模。于是去重文献普遍借助**哈希函数**。([【跳转到 19:25】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1165))

补充一点哈希的背景：哈希函数把输入（如字符串）映射成远小于原始数据的输出（字符串或整数）。哈希**冲突（collision）**指两个不同数据项映射到同一个值。密码学哈希刻意**避免**冲突（比特币就用它）；而用于哈希表的快速哈希**允许**冲突——去重正是利用后者的特性。([【跳转到 19:50】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1190))

### 5.4 精确去重：哈希分组，每组只留一个

**精确去重**概念上特别简单：把每个元素**哈希**，**分组**后每组只留一个，其余删除。实现上可以采用 **MapReduce 风格**（按哈希值分组），因此**易于并行化和扩展**。它操作清晰、精度高，缺点是无法处理近似重复。([【跳转到 20:15】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1215)、[【跳转到 20:40】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1240))

一个经典实例是 **C4（来自 T5 论文）**：它对 Common Crawl 做的精确去重对象是**三个句子的跨度（3-sentence spans）**——若两个文档包含相同的三句跨度，就移除其中一个。要注意这可能有点奇怪：**从文档中间删掉三句话会破坏文本连贯性**，但他们当时就是这么做的。([【跳转到 21:05】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1265)、[【跳转到 21:30】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1290))

![精确去重与 C4：对元素做哈希、分组、每组保留一个（MapReduce 风格，易并行）；C4 以"三句跨度"为单位做精确匹配，代价是可能破坏文档连贯性。](assets/p14/01265.jpg)

但真实世界的数据太混乱，精确去重还不够——**存在大量近似重复**。于是我们需要近似去重。([【跳转到 20:40】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1240))

## 六、去重（下）：用 Jaccard、MinHash 与 LSH 让近似去重线性化

### 6.1 Jaccard 相似度：交集除以并集，取值范围 0 到 1

近似去重第一步是**定义"多相似算相似"**。标准答案是 **Jaccard 相似度**：

```text
Jaccard(A, B) = |A ∩ B| / |A ∪ B|
```

也就是两个集合**交集大小除以并集大小**，取值 0 到 1（0 代表完全无交集，1 代表完全一致）。举文稿里的例子：集合 `A = {1,2,3,4}`、`B = {1,2,3,5}`，交集是 `{1,2,3}`、并集是 `{1,2,3,4,5}`，相除得到 **0.6**。如果两个文档的 Jaccard 相似度超过某个阈值（例如 **0.99**），就认为它们是**近似重复**。([【跳转到 21:55】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1315)、[【跳转到 22:20】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1340))

![Jaccard 相似度与 MinHash：Jaccard(A,B)=|A∩B|/|A∪B|，例中为 0.6；MinHash 是满足 Pr[h(A)=h(B)]=Jaccard(A,B) 的随机哈希函数。](assets/p14/01390.jpg)

### 6.2 MinHash：让"碰撞概率恰好等于 Jaccard 相似度"

现在的问题变成：**如何在线性时间内找出所有 Jaccard 超阈值的文档对？** 好在这是一个已被解决的算法问题，答案分两步，第一步是 **MinHash（最小哈希）**。

**MinHash 是一种随机哈希函数 h，它具有一个关键性质**：

```text
Pr[h(A) = h(B)] = Jaccard(A, B)
```

也就是说，**A 与 B 的哈希发生碰撞的概率，恰好等于它们的 Jaccard 相似度**。

这为什么有用？因为哈希把处理复杂度降到线性。这里有个反直觉之处：一般我们希望哈希**避免**碰撞，让每个元素映射到不同的值；**但在去重里我们恰恰想要碰撞**——而且不是随机碰撞，是要**让越相似的元素越容易碰撞**。([【跳转到 22:45】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1365)、[【跳转到 23:10】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1390))

**MinHash 本身的操作极其简单**：对集合中的**每个元素做哈希，然后取最小值**。

```python
def minhash(S: set[str], seed: int):
    return min(mmh3.hash(x, seed) for x in S)
```

### 6.3 MinHash 为什么成立：用特征矩阵与随机排列来证明

这个性质之所以成立，可以用**特征矩阵（characteristic matrix）**看得很清楚。把集合 A、B 与元素的关系写成矩阵（行是元素、列是集合，`1` 表示该元素属于该集合）：

```text
item | A | B
  1  | 1 | 1
  2  | 1 | 1
  3  | 1 | 1
  4  | 1 | 0
  5  | 0 | 1
```

随机哈希函数等价于在这些元素上**诱导出一个随机排列**（比如排列成 4、3、1、5、2……），然后**看 A 里哪个元素排第一、B 里哪个元素排第一**。每个元素成为"首位"的概率是相同的。于是：

- 若首位是 **1、2 或 3**（A、B 都包含），则 A 的最小数 = B 的最小数，**发生碰撞**；
- 若首位是 **4**（只在 A 中）或 **5**（只在 B 中），则**不碰撞**。

因此，**A、B 最小值相等的概率，恰好等于随机取到"两者共享的那一行"的概率，也就是 Jaccard 相似度**。这就是 MinHash 性质的证明。([【跳转到 23:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1415)、[【跳转到 24:00】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1440)、[【跳转到 24:25】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1465))

![MinHash 的特征矩阵证明：随机哈希在元素上诱导出随机排列，A、B 最小值相等的概率正好等于 Jaccard 相似度。](assets/p14/01415.jpg)

**代码验证**：讲者生成了 **100 个不同的哈希函数**，只检查最小哈希值是否相等，统计碰撞比例，得到的估计值正好是 **0.6**，与真实 Jaccard 一致。关键是：**完全不需要 O(n²) 的两两运算**——只要算 A 的最小哈希、B 的最小哈希，然后看是否碰撞。([【跳转到 24:50】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1490)、[【跳转到 25:15】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1515))

### 6.4 光有 MinHash 还不够：概率太"软"，我们需要锐化

但 MinHash 只说明：**若碰撞，则两者碰撞的概率等于 Jaccard**。这是随机的，方差很大，**没法给出可靠结论**。我们真正想要的是：**只要 Jaccard 超过阈值，就确保 A 和 B 一定（高概率）碰撞**。所以需要把这个概率分布**锐化**，让它更集中。这就需要 **局部敏感哈希（LSH，Locality-Sensitive Hashing）**——理论计算机里的经典思路。([【跳转到 25:40】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1540)、[【跳转到 26:05】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1565))

### 6.5 LSH：分带（banding）让阈值处出现"相变"

LSH 的做法是使用**多个相互独立的哈希函数**，把它们**分带**：

- 把 n 个哈希函数分成 **b 个带（band）**，每个带含 **r 个哈希函数**，满足 `n = b × r`；
- 只有当**某个带内全部 r 个哈希函数都返回相同的值**时，才判定 A 和 B **碰撞**。

例如 `n = 12, b = 3, r = 4`，就把 `h1..h4` 作为第一个带、`h5..h8` 为第二个、`h9..h12` 为第三个。只要有一个带被"触发"，就认为碰撞。([【跳转到 26:30】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1590)、[【跳转到 26:55】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1615))

![LSH 的分带结构：n=b×r 个哈希函数分成 b 个带、每带 r 个；某个带内所有哈希都一致才判定碰撞。](assets/p14/01640.jpg)

**推导碰撞概率**：设相似度为 `s`。

- 某个**固定带**匹配的概率（r 个哈希全部一致）= `s^r`；它随 r 呈**指数级**变化；
- 该带**不**匹配的概率 = `1 − s^r`；
- 所有 b 个带**都**不匹配的概率 = `(1 − s^r)^b`；
- 因此**至少一个带匹配**（即碰撞）的概率：

```text
P(碰撞) = 1 − (1 − s^r)^b
```

举例 `s = 0.8`、`b = 5`、`r = 10`，算出固定带匹配概率约 0.1074，碰撞概率约 **0.4333**。([【跳转到 28:10】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1690)、[【跳转到 28:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1715)、[【跳转到 29:00】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1740))

### 6.6 S 型曲线与"相变"：r 右移、b 左移、中心在 (1/b)^(1/r)

把碰撞概率对相似度 s 作图，得到一条**S 型曲线**——这正是我们想要的：**低于阈值时匹配概率尽量低，高于阈值时尽量高**，在阈值附近发生类似**相变**的陡峭跃变。([【跳转到 29:25】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1765)、[【跳转到 29:50】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1790))

调节参数会移动并改变这条曲线：

- **增大 r**（每带哈希数更多）：指数项更陡，**曲线更尖锐并向右移动**，匹配更难（阈值升高）。例如某对低相似度数据的匹配概率会从 0.25 降到 0.008；
- **增大 b**（带数更多）：**曲线向左移动**，匹配更容易（阈值降低）。

以 `b = 10, r = 10`、相似度区间 0.7～0.98 为例，碰撞概率范围大致从 **0.25 到 1**。([【跳转到 30:15】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1815)、[【跳转到 30:40】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1840)、[【跳转到 31:05】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1865))

![LSH 的 S 型碰撞概率曲线：增大 r 使曲线更陡、向右移（更难匹配）；增大 b 使曲线向左移（更易匹配）。](assets/p14/01815.jpg)

**相变中心的位置**可以解析求出。论文里的例子（Lee 等，2021）：`n = 9000, b = 20, r = 450`。相变阈值约为

```text
threshold ≈ (1 / b)^(1 / r)
```

即 **b 的 1/r 次方的倒数**。若想按"Jaccard 大于 0.9"来过滤，就调整 b、r 让阈值正好是 0.9，并让相变更陡。在临界点上，固定带匹配概率是 `1/b`，碰撞概率会趋近一个常数（≈ **1 − 1/e ≈ 0.64**）——所以相变中心大约就在 0.64，随 b、r 增大，阈值以下趋近 0、以上趋近 1。**代价是 b、r 太大时成本上升**。([【跳转到 31:55】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1915)、[【跳转到 32:20】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1940)、[【跳转到 32:45】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1965))

这套组合就叫 **MinHash + LSH**：LSH 适用于任何哈希函数，而我们在原始数据去重时用 MinHash 来近似 Jaccard 相似度。这就是你应该使用的标准方法。([【跳转到 33:10】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=1990))

## 七、数据配比：别被 epoch 数坑了，以及用 UniMax 给 epoch 设上限

### 7.1 走到这一步，我们要把不同来源整合起来

转换、过滤、去重之后，我们得到一组**规模更小的高质量文档**，但它们来自**多个不同的数据源**（例如 Marin 项目里能看到 Nebula、FinePDFs、机构书籍、代码等）。关键问题变成：**如何把它们整合？** 这本质上是一种**资源分配**——在数据集内部确定一个分布。([【跳转到 33:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2015)、[【跳转到 34:21】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2061))

回顾早期论文 **The Pile**：它为每个组成部分（Component）明确分配了 **Weight（权重）**、**Epochs（轮数）** 和 **Effective Size（有效规模）**，这就是一种朴素的资源分配表。([【跳转到 34:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2075)、[【跳转到 34:40】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2080))

### 7.2 常见土办法：靠感觉、均匀采样、按比例混合

从"第一性原理"（讲者笑称其实不算）出发，你平时可能怎么做？——**靠感觉（vibes）手动调**。这在实践里相当常见。此外有两种机械做法：

- **均匀采样**：在每个数据源上应用均匀分布，每取一个 chunk 就采样一个数据源；
- **按比例混合**：按原始 token 数量采样，`p(s) ∝ num_tokens(s)`，即 token 多的源权重高。

按比例混合通常合理，但**有个大坑**：如果存在一个**体量巨大而质量低下的数据集，它会吃掉大量 token**，这并不理想——直觉上你应该给更高质量的数据源更高权重。([【跳转到 35:05】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2105)、[【跳转到 35:30】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2130))

给权重时有两个约束必须记住：

1. **要保证多样性**：很多数据源之间不可直接比较——文献、代码、论文很难说谁"质量更高"，因为它们根本不是同类东西。若想让语言模型效果好，就**不能把全部质量权重都压在论文上**；
2. **每个数据源的数据量是有限的**：在小数据源上分配过多权重，就会很快用光，**不得不多轮（epoch）重复训练同一批 token**，这会带来负面影响。([【跳转到 35:55】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2155)、[【跳转到 36:20】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2180))

### 7.3 那个关键的算例：50 个 epoch 的过拟合陷阱

第二点非常关键，用一个具体例子拆解。假设只有两个来源：

- **低质量来源**：**10 万亿（10T）token**，很充裕；
- **高质量来源**：只有 **100 亿（10B）token**，很稀缺。

做一个最简单的混合：`p = {"low": 0.5, "high": 0.5}`，训练 **1 万亿（1T）token**。计算每个来源的实际 epoch 数：

```text
low_num_epochs  = (0.5 × 1T) / 10T  = 0.05   # 低质量源只被碰到 5%
high_num_epochs = (0.5 × 1T) / 10B  = 50     # 高质量源要重复 50 遍！
```

也就是说，你会在高质量数据上反复训练 **50 个 epoch**——这极易**过拟合**。这个坑的关键在于：**你只看了质量和分布，却忽略了数据点的实际数量**。讲者特意强调："有些大模型训练项目在这方面搞砸了。"

而正确做法并不是"干脆跑 50 个 epoch"，而是**必须监控数据实际运行的 epoch 数量**。设为 50 的原因是：如果只设定一个混合比例而不全程监控，很容易在不知不觉中跑满 50 个 epoch。顺带说说**混合在训练中如何落地**：通常是在**批次层面**做——对每个元素采样、确定它来自哪个混合分量，再用来自该分量的序列**填满整个批次**。一般每个序列都源自同一个分量，**不是按 token 采样**；为降低方差，一个批次里最好仍包含一些不同的混合成分。([【跳转到 36:45】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2205)、[【跳转到 37:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2255)、[【跳转到 38:25】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2305)、[【跳转到 39:08】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2348))

![数据配比的 epoch 陷阱：低质量源 10T、高质量源 10B，均匀各半训练 1T token，则高质量源要重复 50 遍而低质量源只用到 5%，前者极易过拟合。](assets/p14/02407.jpg)

### 7.4 UniMax：均匀采样 + epoch 硬上限

这个"epoch 太多"的问题其实**早就有人注意到**。**UniMax（Chung 等，2023）** 面向多语言训练的动机正是一些语言资源稀缺。以往做法是"按比例混合再做幂次平滑"（`p(s) ∝ num_tokens(s)^α`，`α ∈ [0,1]`）来让分布更平滑；UniMax 把这件事做得更明确：

> **均匀地采样各个数据源，但为每个数据源的 epoch 数设定一个硬上限 C**——即对每个源 s 满足
>
> ```text
> p(s) × num_training_tokens <= C
> ```
>
> 并给出一个简单流程，在满足该约束的前提下实际确定混合比例。

换句话说，它在"均匀分配"与"避免在小源上反复训练"之间取了一个平衡。([【跳转到 39:58】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2398)、[【跳转到 40:07】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2407)、[【跳转到 40:32】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2432))

## 八、基于回归的配比：用小模型探路，用回归外推出最优混合

### 8.1 为什么要有原则的方法：50 个源就有 50 个待定数字

假设有 50 个数据源，就要确定 50 个权重数字。简单的按比例混合显然不够，或许可以估算某种质量指标再采样，但这**仍属启发式**。所以讲者推荐**最具理论依据、也最清晰易理解**的路线：**基于回归的混合（regression-based mixing）**，代表工作有 **RegMix、OLMo 系列论文**等。([【跳转到 40:57】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2457)、[【跳转到 41:22】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2482))

### 8.2 四步流程：训练代理模型 → 拟合回归 → 优化混合 → 放大训练

核心思路和**缩放定律**很像——**先做低成本计算探路，再大规模扩展**。共四步：

1. **训练一批小规模代理模型**：假设目标是大模型，先缩到约 **3 亿（300M）参数**；对不同的数据混合比例各训练一个小模型，每个给出一个目标指标上的损失值（可以是下游评估指标，也可以是困惑度，由你决定）。例如三成分（Hacker News / GitHub / Philpapers）的不同配比得到若干 `Target` 值（如 5.46、5.57、6.07……）；
2. **拟合回归模型**：以**数据混合权重为输入**、**损失值为输出**训练一个回归器，这样就有了一个低成本函数，能预测"用某种混合训练损失会是多少"；
3. **模拟新混合并预测**：用回归模型对新的混合方案打分，**优化**这个函数，找到预测损失最低的配比；
4. **用最优混合训练大模型**。([【跳转到 41:40】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2500)、[【跳转到 42:05】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2525)、[【跳转到 42:30】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2550))

![基于回归的数据混合（RegMix）四步流程：训练小规模代理模型 → 拟合回归模型 → 模拟新混合并预测目标 → 用最优混合训练大模型。](assets/p14/02500.jpg)

### 8.3 设计选择：混合分布、回归方法、优化目标都要选

具体落地时有几个设计选择：

- **混合分布**：对分布本身建模，很多人选择 **Dirichlet 分布**（也可用指数分布、网格等）；
- **回归方法**：实践中既试过**线性模型**（对数线性模型常常很有效），也试过**梯度提升决策树（如 LightGBM）**；
- **优化目标**：通常参考**下游评估指标**，但**务必警惕过拟合**。([【跳转到 42:50】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2570)、[【跳转到 42:55】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2575)、[【跳转到 43:58】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2638))

**警惕过拟合的现实理由**：预训练本意是训练**通用模型**，而不是迎合某个特定下游评估。举例来说，**若混入大量代码类评估数据，模型会把更高权重分配给所有代码数据**——逻辑不难理解，但最终当你希望模型写诗时，会发现它已经偏科了。因此这一点需格外注意——**按比例混合 / 均匀混合不会陷入这个问题，因为它们不依赖下游评估**。([【跳转到 43:06】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2586)、[【跳转到 43:11】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2591))

论文里还给出了一张**方法对比表**，横跨 RegMix、DML、AutoScale、BiMix、ADMIRE-BayesOpt、CLIMB、OLMIXBase 等方法，列出各自的**代理模型大小**（从 1M 到 350M）、**Swarm 分布**（Dirichlet with natural prior、指数网格、熵加权、动态等）、**回归模型族**（LightGBM、对数线性、幂律、高斯过程等）、**混合优化求解器**（搜索、梯度下降、精确解等）以及**是否带数据重复约束**。这背后是两个希望：

> **希望一**：回归模型在最优解处是准确的；
> **希望二**：最优数据配比能**从小规模迁移到大规模**。

([【跳转到 43:36】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2616)、[【跳转到 44:23】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2663))

### 8.4 两个必须警惕的假设，以及"规模相关的效应"

这个流程建立在两个假设上，都需小心：

1. **回归模型的可靠性**：回归是在一批小规模代理实验上拟合的，我们却拿它去**优化**（逼近极端值）。经典泛化能力通常能保证它在**数据分布范围内**预测准确，但**优化过程会把你推向数据覆盖不足的极端区域**。这是需要注意的点。
2. **配比的规模可迁移性**：我们希望最优配比能从**小规模迁移到大规模**。在开源社区常用规模下，这个假设通常成立（或不明显错误），但**显然存在规模依赖效应**。回想过滤那节的结论：训练越多 token，越能容忍低质量数据——**最优解本来就不一样**。小规模与大规模之间是**成本与精度的权衡**：训练极小的模型结果可能缺乏代表性，但直接在大规模上调超参成本又过高。([【跳转到 44:37】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2677)、[【跳转到 44:54】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2694)、[【跳转到 45:11】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2711))

**具体有多大？** 沿用刚才那个假设例子：海量低质量数据（10T）+ 稀缺高质量数据（10B）。如果用**少量 token 训练小模型**，你可能会把大部分注意力集中在高质量数据上（`p = {"low": 0.1, "high": 0.9}`），因为 token 少、无法多次遍历，"维基百科真香"；但**若沿用这个配比去训练大模型**，就会对高质量数据反复训练，导致**过拟合**。([【跳转到 45:36】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2736)、[【跳转到 46:01】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2761))

### 8.5 两种解法：限制 epoch 与"模拟 epoch"

解决这个规模依赖效应有两条路：

1. **限制 epoch 数**——即 UniMax 那套思路；
2. **模拟 epoch（simulated epoching）**：让**小规模实验"看起来像"大规模实验**。这其实是本课程的一个通用主题——之前讲 **μP（最大更新参数化）**时也见过：对模型重新参数化，让超参能迁移；这里同理。**具体做法**是：既然大模型用 1T token、小模型只用 10B token，就对小模型的数据做 **1% 下采样**，让它"相当于"经历了大规模下高容量阶段会遇到的数据稀缺。注意，简单粗暴的缩放会出问题：**你不能先在小规模上跑完一个 epoch，再在大尺度上重跑一遍**——如果强制只用下采样后的维基百科数据，你会被迫反复训练很多个 epoch，损失居高不下、表现很差。所以优化时必须寻找**更平衡的方案**。([【跳转到 46:26】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2786)、[【跳转到 46:37】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2797)、[【跳转到 47:02】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2822)、[【跳转到 47:27】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2847))

![配比的规模依赖效应与模拟 epoch：小模型数据少时会过度偏向高质量数据；训练大模型时需限制 epoch 或对小模型数据做下采样（simulated epoching）来模拟大规模数据稀缺。](assets/p14/02761.jpg)

**本节收束成一句话**：为不同来源（维基百科、Common Crawl、代码、数学数据等）分配权重时，**基于回归的混合是不错的选择**——先在小规模上拟合"混合权重 → 损失"的函数，优化后再推广到大规模；但必须格外谨慎，因为涉及**轮次控制与过拟合风险**，建议采用**截断轮次**或**模拟轮次**。教训是：**优化任何目标时都要小心，否则很容易优化到错误的方向**。

### 8.6 补讲：怎样自动划分"领域"

课堂还补了一个之前漏讲的点：**领域（domain）的划分**。以 **NLLB** 论文或欧盟的一些工作为例——你拿到一堆 Common Crawl 数据，可以按**主题/领域**（比如 AI2 团队的 **Web Organizer**）归类，同时做**质量过滤**，于是构造出一个**二维网格**：一边是领域、一边是质量，**每个格子就是一个可用于混合的单元**。这是一种**自动确定"领域"**的方式，之后再加上别人提供的现成数据源即可。([【跳转到 49:29】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2969)、[【跳转到 49:54】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=2994))

## 九、后训练数据：高度任务相关，如今几乎全部由强模型合成

### 9.1 从"任务无关"到"任务相关"，合成数据成为主流

前面讲的转换、过滤、去重、配比，基本都属于**预训练 / 中期训练**数据——它们**与具体任务关系不大**，主要用于培养基础技能（RegMix 除外，它虽以最小化损失为目标，但数据本身仍相对任务无关）。到了**后训练**阶段，数据变得**非常依赖具体任务**。([【跳转到 50:08】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3008)、[【跳转到 50:13】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3013))

后训练数据的通用做法是：

1. **定义一组环境**（以代码为例，可能是 GitHub 仓库）；
2. **定义一组任务或提示**；
3. **从强大的教师模型（或人类）收集回复**。

关键事实：**至少在开源社区，几乎所有后训练数据都是合成生成的**——人类标注既慢又贵。当然，若处于技术前沿，几年前确实不得不花钱雇很多人来提供回复，如今即便在前沿也可以采用**人机混合**。([【跳转到 50:38】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3038)、[【跳转到 51:03】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3063))

### 9.2 OpenThoughts：120 万个实例，教学效果≠模型强弱

**OpenThoughts** 的目标是获取高质量后训练数据，最终用教师模型生成了 **120 万个实例**。数据来源包括 **Stack Exchange、NuminaMath** 等人工来源，以及部分合成数据，涵盖编程、数学、化学等领域。流程大致是：把各来源数据输入 → **去重和随机采样**（对问题下采样）→ **生成多个答案** → 整合成最终数据集。这里的 **120 万指样本总数，除以 16 才是实际问题的数量**（每个问题采样多个答案）。([【跳转到 51:25】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3085)、[【跳转到 51:50】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3110)、[【跳转到 52:45】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3165)、[【跳转到 52:50】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3170))

他们对"该怎么生成回复"做了全面分析，几个反直觉结论：

- **只用少数几个来源，反而比把所有来源都用上更好**；
- **对每个问题多采样几次（如 16 个）是有帮助的**；
- **更好的模型不一定是更好的老师**：**QwQ-32B**（当时算较老较小的模型）的**教学效果比 DeepSeek-R1**（当时最强的开源模型之一）更好；这说明模型性能与教学质量并不等价；
- **简单的答案过滤效果有限**；
- **小而精的高质量来源（如 OpenMath-2-Math）优于大而杂的来源**。([【跳转到 51:58】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3118)、[【跳转到 52:20】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3140))

![OpenThoughts 数据流水线：来源筛选 → 去重 → 随机采样 → 生成多个答案 → 汇总；分析显示少数精良来源、多样本采样更有用，且 QwQ-32B 的教学效果优于 DeepSeek-R1。](assets/p14/03170.jpg)

### 9.3 SWE-smith 与 SWE-Zero：从"会写代码"到"会做软件工程"

最近学界特别感兴趣的是**真正的编码模型**——不只是能生成代码，而是**真正能进行软件开发**。这催生了一批软件工程（SWE）数据集。

**SWE-smith（Yang 等）** 的思路是：拿一个代码仓库，用**语言模型自动生成任务**——设计一个智能体，把仓库配置成**可运行状态**（安装各类依赖），然后通过修改代码（例如**故意引入 bug**）生成任务，验证通过后成为任务实例。这些属于**合成任务但环境真实**，**128 个 GitHub 仓库可产出约 5 万个任务**。([【跳转到 53:15】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3195)、[【跳转到 53:26】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3206)、[【跳转到 53:51】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3231))

![SWE-smith：给定仓库，用语言模型自动生成任务（程序化修改、LM 生成、组合、PR 镜像），128 个仓库产出约 5 万个合成任务。](assets/p14/03195.jpg)

**SWE-Zero（英伟达）** 则发现了 SWE 任务的特殊性：与数学题不同，SWE 任务往往有**大量重型依赖项**，大多数 GitHub 仓库**无法直接运行**，回退到某个 commit 再安装过时依赖简直是噩梦，为成千上万个仓库单独配置 Docker 镜像更是基础设施层面的灾难。他们的关键观察是：**强模型在不少任务上不需要代码执行反馈也能处理**——允许执行代码时得分约 **80**，禁止执行也能接近 **70**，说明模型对代码语义已有一定理解。

据此，他们生成了约 **30 万条真实 GitHub PR 的智能体轨迹**，并进一步扩展到 **1200 万条轨迹**；训练时先在一批样本上微调，再在 SWE-bench 上微调。后续的 **SWE-rebench** 也是类似的"抓取大量 PR"思路：获取一批仓库、尝试安装（大多数会失败），而 SWE-Zero 的优势在于**非常轻量**（回顾他们让代码执行的尝试：最终只有约 **3.2 万个成功执行、12 万个未能执行**）。([【跳转到 53:58】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3238)、[【跳转到 54:29】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3269)、[【跳转到 54:54】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3294)、[【跳转到 55:26】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3326)、[【跳转到 56:16】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3376))

### 9.4 合成程度是一种连续谱：全合成 / 半合成

最后归纳出一组权衡：后训练数据可以是

- **完全合成**；
- **半合成**：环境真实但任务合成，或任务真实但环境合成。

回复通常来自**能力强、同时具备良好教学能力**的模型。代码环境的处理与过滤细节很多，本讲无法逐一展开。从**数学这类无需环境的数据集**，过渡到**编程领域**，数据集规模的增长幅度相当大——但总体思路始终是：**你拥有提示词，然后从教师模型收集回复**。([【跳转到 55:19】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3319)、[【跳转到 56:40】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3400)、[【跳转到 56:51】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=14&t=3411))

## 小结

![本讲总结：过滤是训练分类器（语言、质量、毒性）识别"好数据长什么样"；去重用哈希扩展到大规模模糊匹配；配比在小规模试比例、外推到大规模；后训练数据形似评估、使用合成数据；很多数据工作是领域相关、要盯着具体例子做的。](assets/p14/03463.jpg)

1. **流水线四环节**：转换 → 过滤 → 去重 → 配比，每一步的输入都是上一步的输出；后训练数据另起一段。真实数据工作比课堂呈现的要琐碎、且高度依赖具体领域。

2. **转换**：原始数据不是文本（HTML / PDF / 代码目录），要线性化成 token 序列，这是**有损**过程。HTML→文本移样板、抽正文，"什么算内容"界限模糊；常用**基于规则**的快工具（trafilatura、resiliparse、jusText、lynx），其中 resiliparse 在 DCLM 评测里表现好。PDF 占比小但**平均质量高**，扫描件需 VLM 做 OCR。

3. **过滤**：通用框架是"给定目标数据 T 与原始数据 R，选出相似子集 T′"，要求**能泛化**且**极快**。分类器分**生成式（KenLM 的 5-gram）**与**轻量分类器（fastText 线性模型）**两类。实例包括语言识别（Meta 支持 176 种语言、Dolma 保留 `p(English)≥0.5`）、数学语料 OpenMathText（规则 + KenLM 困惑度 < 15000 + fastText 阈值，14.7B token 训练的 1.4B 模型胜过 20 倍未过滤数据）、GPT-3 的线性分类器、微软 phi 的 GPT-4 教育价值筛选 + 廉价分类器、Jigsaw 毒性过滤。**不存在最优阈值**：训练越久越能容忍低质量数据，越过重复遍历的临界点后会过拟合。

4. **去重**：完全重复 + 近似重复无处不在（镜像站、fork、MIT 许可证、模板文章，C4 里某防毒面具描述出现 6.1 万次）。动机是高效训练、防记忆/隐私、省算力，而**去污染（测试集不泄漏）更重要**。去重的核心难点是避免 O(n²)，所以用哈希。**精确去重**：哈希分组、每组留一个（如 C4 的"三句跨度"）。**近似去重**：Jaccard 相似度 → MinHash（`Pr[h(A)=h(B)]=Jaccard(A,B)`，由特征矩阵 + 随机排列证明）→ LSH 分带（`P=1−(1−s^r)^b`）形成 S 型相变曲线；增大 r 右移变陡、增大 b 左移，相变中心约 `(1/b)^(1/r)`、临界碰撞概率约 0.64。

5. **配比**：要在**质量、多样性、每个源的 epoch 数**之间权衡。按比例混合会让"体量大而质量低"的数据源吃掉大量 token；在小数据源上分配太多权重会导致 **50 个 epoch 的过拟合陷阱**（低质量源 10T、高质量源 10B、各半训 1T 的算例）。**UniMax** 用"均匀采样 + epoch 硬上限 `p(s)·num_tokens ≤ C`"解决。

6. **基于回归的配比（RegMix 等）**：四步——训练小代理模型 → 拟合"混合权重→损失"回归 → 优化预测最优混合 → 放大训练。设计选择包括 Dirichlet/指数混合分布、线性/LightGBM 回归、以（谨慎对待的）下游评估为优化目标。两个假设要警惕：回归在最优点处准确、最优配比可从小规模迁移；规模依赖效应真实存在，用**限制 epoch** 或**模拟 epoch（对小模型数据下采样）**应对。**优化目标时务必小心，否则会优化到错误方向**。

7. **后训练数据**：高度任务相关，通用流程是"定义环境与任务 → 从教师模型（或人类）收集回复"，开源社区几乎全用合成数据。**OpenThoughts** 生成 120 万实例（问题数 ÷ 16），发现少数精良来源更好、多样本采样有用、QwQ-32B 教学效果优于 DeepSeek-R1、简单答案过滤作用有限。**SWE-smith** 用 128 个仓库产出约 5 万合成任务；**SWE-Zero** 指出 SWE 任务依赖重、Docker 配置是灾难，但强模型无需执行反馈也能接近 70 分（允许执行约 80），生成 30 万真实 PR 轨迹并扩展到 1200 万。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| 数据流水线（pipeline） | 转换 → 过滤 → 去重 → 配比 四道工序的串联，后接后训练数据处理 |
| 转换（transformation） | 把 HTML/PDF/代码目录线性化为 token 序列；有损，常用基于规则的工具 |
| 样板（boilerplate） | 网页中的页眉、页脚、菜单、广告等非正文内容，转换时通常删除 |
| 目标数据 T / 原始数据 R / 子集 T′ | 过滤框架：用高质量小集合 T，从海量 R 中选出相似子集 T′ |
| KenLM / 5-gram | 低成本生成式语言模型，用于给"是否像目标数据"打分（如困惑度阈值） |
| fastText | 快速线性（词袋）分类器，过滤中最常用的轻量分类器 |
| 语言识别 | 判断文本语言的分类任务；Meta 模型支持 176 种语言，Dolma 保留 p(English)≥0.5 |
| 困惑度（perplexity） | 语言模型对文本的"意外程度"，OpenMathText 保留其 < 15000 的文档 |
| 去重（deduplication） | 移除重复数据；分精确去重与近似去重 |
| 去污染（decontamination） | 确保测试集数据未出现在训练集中，防止评测泄漏 |
| Jaccard 相似度 | \|A∩B\|/\|A∪B\|，取值 0~1，衡量两个集合的重合程度 |
| MinHash | 满足 Pr[h(A)=h(B)]=Jaccard(A,B) 的随机哈希，可用最小值实现 |
| 特征矩阵 | 行=元素、列=集合的 0/1 矩阵，用来证明 MinHash 性质 |
| 本地敏感哈希（LSH） | 把 n 个哈希分成 b 个带、每带 r 个，使碰撞概率呈 S 型相变 |
| 分带（banding） | LSH 的核心：某个带内全部 r 个哈希一致才判定碰撞 |
| 碰撞概率公式 | P = 1 − (1 − s^r)^b；r 右移变陡、b 左移变易，中心约 (1/b)^(1/r) |
| 均匀采样 / 按比例混合 | 配比的两种朴素做法：各源等权；或按 token 数 `p(s)∝num_tokens(s)` |
| epoch（轮次） | 同一份数据被完整训练的遍数；小数据源上过多 epoch 会导致过拟合 |
| UniMax | 均匀采样 + 对每个源的 epoch 数设硬上限 C 的配比方法 |
| 基于回归的混合（RegMix） | 用小代理模型拟合"混合权重→损失"，优化后外推到大规模 |
| Dirichlet 分布 | 常用于建模数据混合比例的分布，便于采样不同配比 |
| 模拟 epoch（simulated epoching） | 对小模型数据下采样，使其"像"大规模高容量阶段的数据稀缺情形 |
| 后训练数据 | 高度任务相关的数据，通用流程是定义环境/任务并从教师模型收集回复 |
| 合成数据 | 由强模型生成的数据；开源社区后训练数据几乎全部合成 |
| OpenThoughts | 生成约 120 万后训练实例的数据集，强调教学效果与来源质量 |
| SWE-smith | 从 128 个仓库自动生成约 5 万个软件工程合成任务 |
| SWE-Zero | 英伟达工作：强模型无需执行反馈也能处理 SWE 任务，生成 30 万→1200 万条轨迹 |
