# Lecture 3: Architectures

## 本讲要解决的核心问题（SCQA）

**背景（Situation）**：今天几乎所有大语言模型（LLM）都基于同一个骨架——**Transformer**（2017 年 Vaswani 等人提出的一种神经网络结构）。在"密集注意力"这个范畴里，它的整体形式其实相当经得起时间考验，并没有被大改。

**冲突（Complication）**：真正难的不是"能不能搭出来"，而是"**该怎么选**"。归一化放在哪、用什么激活函数、位置信息怎么加、前馈层设多大、词表多大……可选项成百上千，而且**没有一个简单理论能直接告诉你答案**。更糟的是：如果训练到一半模型突然崩了（loss 爆炸），可能几百万美元算力就打水漂，甚至再也救不回来。讲者 Tatsu 用一句话概括这堂课的主题："关于架构和超参数，**你本不想知道的一切**"。

**疑问（Question）**：面对这么多选择，到底哪些是"必须遵守的定式"，哪些可以随便调？

**回答（中心思想）**：把主流模型（GPT / LLaMA 系）的实际做法摊开来看，你会发现——**真正被广泛采纳的核心改动其实很少**，而且**大多数看起来吓人的超参数都有很宽的安全区**。真正需要提心吊胆的，是会让训练崩溃的**稳定性问题**，而它的根源几乎都指向 **softmax**。本讲就是一张"业界共识地图"，帮你在做作业、刷排行榜时知道该抄什么、该警惕什么。

讲者采取的是一种"**全盘托出**"的策略：他会把所有最新论文过一遍，把每年发布的新模型一个个梳理出来（Qwen、Gemma、InternLM、Nemotron、OLMo 等），从中看出**哪些选择大家高度一致、哪些五花八门**。他给了两条学习路径：最好的办法是**亲自训练模型、换不同架构去试**；但我们没有那么多算力与时间，所以次优解是**从别人的经验里找共识**。[【跳转到 02:26】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=146)

本讲的路线图分四步：先讲**常见架构变体**（归一化、激活函数、位置编码这些"零件"），再讲**超参数**（前馈层比率、头维度、纵横比、词表大小），然后是**训练稳定性**技巧，最后讲注意力层面面向**部署**的优化（MQA/GQA、滑动窗口注意力）。[【跳转到 04:14】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=254)

按"从最稳定的共识，到最活跃的探索"排列，本讲分十个要点展开。

## 一、架构没有理论可依，它是在"表达能力 × 训练稳定 × 系统效率"之间的权衡

### 1.1 架构必须同时满足三件互相打架的事

为什么架构这么"乱"、这么不优雅？因为一个架构**必须同时满足三种需求**：

1. **能学（表达能力）**：要有足够的能力从数据里学出规律、能泛化；
2. **跑得快（系统效率）**：要在 GPU 上高效训练与推理；
3. **不能崩（训练稳定性）**：训练到一半损失突然爆炸、再也救不回来，是灾难性的。

正因如此，很多设计并不优雅，是被现实"逼"出来的。"优雅"在这里不是目标，**能同时摆平这三件事才是**。[【跳转到 04:44】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=284)

### 1.2 共识是怎么形成的：从"群雄混战"到 LLaMA-2 统一

回顾历史能看到这种"共识"的演化：从 Transformer 刚出现到 GPT-3 那段，大家做了各种实验、**还没有黄金标准**；直到 **LLaMA-2** 发布，大家说"哇，我也想要一个那样的模型"，于是纷纷开始训练 LLaMA-2 的微调变体；**前一年**的趋势是"改架构让训练更稳定"，**这一年**的趋势则是"通过架构变体支持更长的上下文依赖"。[【跳转到 05:36】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=336)

### 1.3 一个反直觉的认识：几乎无法事前推理

讲者反复强调：这些架构选择**很难靠纯推理得出**。我们事前并不知道"去掉偏置项"是可行的、不知道"RMSNorm 和 LayerNorm 一样好"，这些都是**基于大量实验和集体积累的经验**才成为共识。数据规模远超算力（即使在 Google 也是如此），所以只能靠"观察大量模型 + 亲自训练"来建立直觉。这也是 Percy Liang 和 Tatsu 设计这门"从零构建"课程的原因。[【跳转到 16:08】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=968)

![图注：本讲的路线图——先讲架构变体（归一化、激活函数、位置编码），再讲超参数、稳定性技巧与注意力层面的部署优化。](assets/p03/00254.jpg)

## 二、归一化应移出残差流——pre-norm 是现代模型的普遍共识

### 2.1 残差流：贯穿网络的一条"主干道"

Transformer 里有一条贯穿整个网络的"主干道"，叫**残差流（residual stream）**，记作 `x`。每个组件（注意力 Attention、前馈层 MLP）先算出一个"增量"，再**加回**到这条主干道上。有了这条通道，梯度在反向传播时就能顺着它顺畅地回溯，网络才容易训练。

### 2.2 原始 Transformer 的"唯一错误"：把 LayerNorm 放进了残差流

原始 Transformer 论文在每个组件的**末尾、残差流内部**放一个 LayerNorm，这叫 **post-norm**。讲者说：很多人认为 Transformer 团队几乎什么都做对了，**唯独这一点做错了**——LayerNorm 的位置。[【跳转到 06:17】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=377)

现代主流做法是把归一化**移到残差流外面、在每个组件计算之前**，这叫 **pre-norm**（前置归一化）。它可以放在多头注意力之前，也可以放在 FFN 之前。几乎所有现代语言模型都这么做。罕见的例外是 **OPT-350M**：它在残差流里仍用 post-norm，讲者调侃 OPT 系列整体比较"乱"，不明白为什么单单这个模型这样处理。[【跳转到 07:07】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=427)

![图注：残差流示意——`x` 从底部一路贯穿到顶部，各组件把计算结果加回主干道；原始 Transformer 把 LayerNorm 放在残差流内部（post-norm）。](assets/p03/00427.jpg)

### 2.3 为什么 pre-norm 更好：最初动机是"想去掉预热"

这项研究的**最初动机**是想解决一个问题：训练 Transformer 通常要做**学习率预热（warmup）**（开始时用很小的学习率，再逐步升高）。有人想"如果能把预热去掉就好了"。但很快发现，去掉预热会带来严重的稳定性与收敛问题：用原始的 post-norm，收敛效果明显更差；而换成 pre-norm，即使不做预热也能获得好得多的收敛。[【跳转到 07:32】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=452)

![图注：pre-norm 与 post-norm 的收敛对比——post-norm（紫色虚线）收敛更差；pre-norm 即使在无预热设置下也明显更好。](assets/p03/00502.jpg)

### 2.4 更本质的原因：让残差流保持"干净"

真正让人信服的理由是两条：

- **梯度直通**：pre-norm 下 `x` 从底部进入，一路直通到顶部、直达最终输出。反向传播时梯度可以沿着这条"直路"直接回传，于是无论网络多深，**梯度的规模基本保持不变**。
- **避免梯度尖峰**：post-norm 每经过一个 Transformer 模块都要做一次 LayerNorm，会不断改变梯度的范数，容易产生**梯度尖峰**。研究表明 pre-norm 下梯度尖峰的幅度和频率都有改善。

讲者引用了最早仔细研究这一现象的工作（幻灯片标注为"SAZR 等"），并总结：**"保持残差流干净"**是架构设计的一条核心直觉，这也解释了为什么"把 LayerNorm 移出残差流"基本被所有人采纳。[【跳转到 09:00】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=540)

### 2.5 变体：放到计算之后、"到处加 norm"

- 也有模型把归一化放在**计算之后**（但仍在残差流之外），例如一些近期模型。
- 还有一条诚实到有点"荒谬"的经验：**遇到稳定性问题，就在各处多加一些 LayerNorm**（比如往注意力里也塞一个），通常真的有用。有时你会看到"double norm"（同处用两个 LayerNorm）。[【跳转到 10:18】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=618)

## 三、RMSNorm 取代 LayerNorm，并顺手去掉偏置项

### 3.1 RMSNorm：不减均值、不加偏置

原始的 **LayerNorm** 会：减去均值、除以方差、再缩放回来（并且带一个偏置项）。这完全没问题——很多模型都成功这样训练过。

而现代模型基本都换成了 **RMSNorm（均方根归一化）**：它**不减均值、也不加偏置**，只做一次按"均方根"的缩放。数学上 LayerNorm 的表达能力其实**更强**，所以从纯表达能力角度看，并没有非用 RMSNorm 不可的理由；但在实践中 **RMSNorm 的建模效果和 LayerNorm 一样好，却运行更快**。[【跳转到 11:32】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=692)

![图注：LayerNorm 与 RMSNorm 的公式对比——RMSNorm 去掉了减均值和偏置项，只保留按均方根的缩放。](assets/p03/00692.jpg)

### 3.2 为什么更快：算术强度与"系统/架构协同设计"

这里涉及到"**系统和架构的协同设计**"（上一讲提过**算术强度**这个概念）。算术强度可以粗略理解为"做计算的时间 vs 搬数据的时间"：

- 我们要让 GPU 保持"高负载"，方法是做**矩阵乘法**这类高强度的计算；
- 像 LayerNorm 这样的**统计归一化操作算术强度极低**——它需要大量**内存搬运**，却只有很少的计算，是"吃内存"的操作。

LayerNorm 只占系统浮点运算量（FLOPs）的约 **0.17%**，但关键不在 FLOPs 占比，而在**运行时间**：根据工作负载和具体设置，它可能占到运行时间的很大比例（讲者提到小型模型上甚至约 25%）。所以去掉"减均值 / 加偏置"这部分，是几乎**零成本的优化**。有 Google 论文显示，切换到 RMSNorm 后，即使参数量不变，性能也有所提升，等于"白赚"一个系统优化。[【跳转到 12:05】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=725)、[【跳转到 13:31】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=811)

### 3.3 顺便去掉偏置项

同理，线性层原本带的 **偏置（bias）** 也是"低算术强度、相对更吃内存"的操作，所以大多数实现直接把偏置完全去掉。有时偏置还会引发不稳定。讲者说，去掉它的主要理由其实就是**让系统更简单**——这也是一个免费的系统优化。[【跳转到 14:53】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=893)

### 3.4 注意：这些"能不能去"无法事前推理

这里最重要的一课是：我们**事前并不知道**"去掉偏置项"是可行的。但基于大量实验及集体积累的知识，我们大致知道——对于典型的语言建模任务，在线性层和 RMSNorm 上去掉偏置项是可行的。这一点必须靠实验和观察得出结论。

## 四、激活函数的关键是"门控线性单元（GLU）"

激活函数的名字很多：ReLU、softmax、GELU、Swish、GLU、SwiGLU……听起来吓人，但其实有一条清晰的主线。你**用最朴素的激活函数就能训练语言模型**：比如 Chinchilla 就用了较朴素的激活并表现很好；GPT-2/GPT-3 用的是 **GELU**（高斯误差线性单元），它和 ReLU 的区别只是零点附近有一个微小的凹陷，基本不影响大部分激活区间。而**真正的主流是门控线性单元（GLU, Gated Linear Unit）**——几乎所有靠谱的现代语言模型都用某种 GLU。[【跳转到 16:33】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=993)

### 4.1 GLU 的结构：给激活加一道"门"

普通前馈层（FFN）是：`x → W1 → 激活 → W2`。**GLU 的想法**是再引入一个"**门**"矩阵 `V`，用它算出的结果**逐元素乘**到激活输出上：

```text
普通 FFN:   W2 · act(W1 · x)
GLU:        W2 · ( act(W1 · x) ⊙ (V · x) )
```

其中 `⊙` 是逐元素相乘。"门"可以**动态调节**信号强弱——这是一条很通用的有效技巧，讲者称之为架构设计里非常有效的"原语（primitive）"。[【跳转到 18:06】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=1086)

![图注：门控线性单元（GLU）——在普通前馈层上再加一个"门"矩阵 V，用它与激活输出逐元素相乘来调节信号。](assets/p03/01136.jpg)

### 4.2 两个主流变体：GeGLU 与 SwiGLU

- **GeGLU**：激活用 GELU，Google / T5 / Gemma 系常用；
- **SwiGLU**：激活用 Swish（即 `x × sigmoid(x)`），LLaMA、PaLM 的后代几乎都用它。

讲者说 SwiGLU 大概是更主流的一个，但两者其实**差别不大**。[【跳转到 19:30】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=1170)

### 4.3 关键冷知识：为了参数量对齐，前馈维度要缩到 2/3

引入门矩阵 `V` 后，前馈层从 2 个矩阵变成 3 个矩阵，参数量变多。为了**保持总参数量不变**，通常会把**前馈维度缩小到原来的约 2/3**。Shazeer 那篇著名的 GLU 变体论文做了参数对齐的对比，结论是 **GLU 变体几乎总是一致地更好**；Google 2020 年的大规模对比（Narang 等人，用 T5 架构）也支持这一点。[【跳转到 20:27】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=1227)

### 4.4 例外与结论

当然也有例外：GPT-3 没用 GLU；有模型用了"平方 ReLU"这种看似"疯狂"的选择也照样能跑。但**很少见到完全不用门控的模型**。证据一致表明：使用门控技巧能带来几乎不增加计算成本的性能增益。[【跳转到 21:41】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=1301)

## 五、并行块曾短暂流行，如今已被串行块取代

### 5.1 串行块是默认，并行块是"系统优化"尝试

默认的 Transformer 块是**串行**的：先算注意力，再算 MLP，一个接一个。从系统角度看这像是一个瓶颈——"必须等前一个算完才能算下一个"。于是有人提出：能不能把注意力与 MLP **并行计算**，再把两者的输出相加后一起加回残差流？

![图注：并行 Transformer 块——把注意力与 MLP 并排计算、输出相加后加回残差流；而串行结构是一个接一个计算。](assets/p03/01371.jpg)

**并行块**最早出现在 **GPT-J**（一个 GPT-3 的开源复现）。好处是很多组件可以复用：LayerNorm 可以共享、矩阵乘法可以融合，从而有机会做进一步的系统优化。PaLM 报告里就采用了这种描述。Cohere（其创始人之一是 Transformer 作者之一）受 Google 影响也采用了这套架构。[【跳转到 22:51】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=1371)

### 5.2 为什么现在不流行了：等于把深度减半

过去两年这种方法**不再流行**，主要原因是：

- **串行形式的优化已经做得足够好**了；
- 并行"相当于把模型深度减半"，会损失表达能力，**为了这点系统收益不划算**。

当年 PaLM 论文宣称并行"没有性能下降、系统利用率还提升了 15%"，只看那篇论文你会觉得效果一样好。但后来 Google 的许多模型也不再采用它——讲者认为这本身就是一个"其实有代价"的隐含信号（不过据他所知，没有人做过控制良好的"并行 vs 串行"消融实验）。[【跳转到 24:06】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=1446)

## 六、RoPE 用"旋转"编码相对位置，成为 2024 年后的主流

### 6.1 注意力天生不知道位置

**注意力机制本质只是内积运算，它天生"位置无关"**：把一组词任意打乱，注意力的结果不变。所以必须**显式地给模型注入位置信息**。历史上出现过三类做法：

- 原始 Transformer：**正弦 / 余弦**位置编码（类似傅里叶变换的直觉）；
- 很多模型：**绝对位置嵌入**（每个位置对应一个独立的嵌入向量）；
- Google 系（T5、Chinchilla）：**相对位置嵌入**（把"两个位置相差多远"加到注意力矩阵里，而不是加到 K/Q 向量上）。

![图注：位置嵌入的演进——正弦/余弦、绝对位置、相对位置，最终 RoPE 成为 2024 年后占据主导的方案。](assets/p03/01624.jpg)

### 6.2 RoPE 的核心思想

**RoPE（旋转位置编码，Rotary Position Embedding）** 是 2024 年后绝大多数模型的选择。它的来历很有意思：据说最早源于 GPT-J，由一位研究员在一篇不太知名的博客与配套论文中提出，思想相当漂亮。它属于**相对位置嵌入**——我们希望"两个词的内积"只依赖于它们的**相对距离**，而与绝对位置无关。

关键几何事实是：**内积对"旋转"是不变的**。思路如下：

- 取用与位置无关的"语义词向量"作为起点；
- 根据词出现的位置，对这些向量**旋转一个角度**（位置 0 不转，位置 1 转一个单位角度，位置 2 转两个单位……）；
- 这样一来，两个词之间的**相对角度差只取决于它们的距离**，无论它们出现在句首还是句尾，内积结果都一致。

高维怎么办？最简单的办法是**把向量每两个分量分成一组**，每组用**不同的旋转频率**去旋转：低频旋转慢、能捕捉长程依赖；高频旋转快、能捕捉"是否相邻"这类短程信息。[【跳转到 27:04】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=1624)、[【跳转到 28:19】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=1699)

![图注：RoPE 的直觉——用位置对向量做旋转，两个词的相对角度只取决于它们之间的距离，而与绝对位置无关。](assets/p03/01744.jpg)

### 6.3 怎么实现，以及与正弦嵌入的区别

实现上：用正弦、余弦生成与"位置 id"对应的角度，**对查询（Q）和键（K）施加旋转**，再进入注意力计算，即 `X · W · R(X)`（R 是旋转矩阵）。位置信息是在**注意力计算时**注入的，而不是加在最底层的词嵌入上。这一点非常重要：正弦/余弦嵌入会产生"位置与词之间的奇怪交叉项"，从而泄露绝对位置；而 RoPE 用**相乘**的方式（而非当作嵌入相加），天然没有交叉项、**完全是相对的**。[【跳转到 31:13】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=1873)

### 6.4 几个延伸讨论

- **为什么相对位置嵌入"不算真正的嵌入"**：像 T5 那类相对位置做法是**直接加到注意力矩阵**上，你没法从中拆出"内积结构"。若要严格满足"内积只依赖相对距离"且能分解成 `f(x_i)·f(y_j)` 的形式，RoPE 是自然浮现的解法。
- **部分旋转（partial RoPE）**：只旋转一部分（例如前两个）坐标也能用。直觉是低频成分旋转幅度小，在极小模型里显存紧张时可以省掉。
- **其他方案**：像 ALiBi 这类直接注入注意力矩阵的方法也相当有效，但并非当前主流。

## 七、超参数大多有很宽的安全区，真正主导效果的是算力

只有当你真正要"实例化"一个模型时，才会开始琢磨这些底层细节：前馈层多大？注意力头多少？词表多大？权重衰减和 dropout 设多少？需不需要正则化？这些看似吓人，但**人们实际尝试过的方案空间其实相当小**，每个关键超参数都有一片"安全区"。

### 7.1 前馈层比率（FFN ratio）：默认 4 倍，GLU 时缩到约 2.67

前馈层大小指 MLP 中第一次矩阵乘法的输出维度与模型隐藏维度之间的比例，它控制 MLP 的"丰富程度"：

- **朴素经验值约为 4 倍**（隐藏维度的 4 倍），效果出奇地好；
- 用 GLU 时多了一个矩阵，为保持总参数不变，缩到约 **2/3**，于是落到约 **2.67**；
- **LLaMA-2** 团队觉得自己的注意力头（MQA）很高效，就随手把比例乘了约 1.33，得到约 **3.5**，更侧重 MLP 一些；
- 非门控模型则是 **4**。

![图注：前馈层比率的安全区——损失对具体取值并不敏感，只要落在"盆地"里就没问题。](assets/p03/02238.jpg)

**激进的例外**：Google 的 **T5** 决定不遵循"4 倍"经验法则，而用了高达约 **64 倍**的乘数。他们的系统论证是"矩阵乘法做得越大，硬件利用率越高"。这确实是个惊人的例外。但有趣的是，T5 的后续改进版本又回归了标准做法——这本身说明激进选择在计算效率上可能很低。Kaplan 等人 2020 年的缩放定律论文做了一个扫描实验，发现存在一个"**盆地**"：从约 1 到约 10，损失对具体取值**不敏感**；只有完全选错（比如超过 10~100）损失才会急剧上升。所以 2.67、3.5、4 这些选择其实都落在安全盆地内。[【跳转到 38:54】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=2334)、[【跳转到 40:34】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=2434)

### 7.2 头维度（head dim）：让 d_head × 头数 ≈ 模型维度

标准做法是：如果你有多个注意力头，确保**头维度 × 头数 ≈ 模型维度**（即 `d_head ≈ d_model / H`），比例大致在 **1 附近**。这只是一条经验法则，并非必须，但大多数模型都遵循它，而且效果不错。它同样是个**容错率很高**的超参数，消融实验显示 1 附近有很宽的缓冲区间（显著例外是 T5）。[【跳转到 41:24】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=2484)

### 7.3 纵横比（aspect ratio）：d_model / 层数 ≈ 100

**纵横比**指模型的"宽度 / 深度"。放大模型时，大家通常**固定一个纵横比**整体放大，所以它决定了"深度与宽度"的权衡：

- **越深**：表达能力可能越强，但从系统层面很难处理——沿深度切分层需要"**流水线并行**（pipeline parallelism）"，这是大多数人极力避免的；
- **越宽**：更容易并行（"**张量并行**（tensor parallelism）"），系统层面友好得多。

系统原因把大家推向了"宽"的方向，最终结果大致落在 `d_model / 层数 ≈ 100`（GPT-3、LLaMA 等都符合）。Kaplan 等人的扫描也显示不同规模模型的最佳纵横比都接近 100。另有研究比较各种深度/宽度权衡后总结：**真正主导效果的是 FLOPs（总计算量）**——计算量越大性能越好——而不一定是纵横比。[【跳转到 43:38】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=2618)、[【跳转到 45:13】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=2713)

![图注：纵横比——大多数现代模型都落在 d_model / 层数 ≈ 100 的区间，很少做得特别深或特别宽。](assets/p03/02618.jpg)

### 7.4 词表大小：单语约 3 万，多语 / 生产级 10 万~20 万

词表大小上有很明显的两类分野：

- **单语模型**（只做英语）：词表较小，约 **3 万**；
- **多语 / 生产级模型**（LLaMA 衍生、GPT-4 类前沿模型）：词表大得多，约 **10 万~20 万** token，Google 模型的词表往往更大。

多语模型确实需要更大的词表来覆盖整个语言空间；同时已有的缩放定律表明**模型越大，能容纳的词表也越大**，所以这也部分受现代模型规模趋势的影响。现在几乎没人再训练"大型单语预训练模型"了。[【跳转到 45:52】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=2752)、[【跳转到 46:25】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=2785)

![图注：词表大小的两类分野——单语模型约 3 万，多语 / 生产模型 10 万~20 万。](assets/p03/02785.jpg)

### 7.5 附带讨论：不同分词器能公平比较吗？

只要**不改动序列**（现代分词器是"完整"的，能建模任意序列），并用**字节数归一化**（即用 **bits-per-byte，BPB** 衡量），比较就是有效的。困惑度（perplexity）与 bits-per-byte 互为对偶，在可比条件下可以互相换算，但要注意你改变的到底是哪个变量。[【跳转到 48:30】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=2910)

## 八、正则化反直觉——单遍训练几乎不过拟合，weight decay 更像优化技巧

### 8.1 标准论证：语言模型根本不过拟合

按机器学习的常规直觉，为了防过拟合，你会用 **dropout** 或 **权重衰减（weight decay）**。但语言模型的处境恰恰**相反**：

- 语言模型是"**算力受限**"的：数据量远超你能处理的算力（即使在 Google，互联网数据量也超过可用 FLOPs）；
- 因此你通常**只会把语料遍历一遍**（single epoch），根本不会看到同一份数据两次；
- 而单遍 SGD 有充分理由被认为"记不住"数据——也就是说，**过拟合几乎从来不是问题**。

既然不过拟合，理论上**完全可以不用正则化**。实验也支持这一点：加不同强度的 weight decay，训练损失与验证损失几乎**没有差别**（因为本来就没过拟合，训练损失与验证损失基本重合在一条线上）。

### 8.2 那为什么现代模型还在用 weight decay？

研究发现：**weight decay 往往不是在防过拟合，而是在与优化器、学习率衰减相互作用**，让优化更容易收敛到更好的极小值——它更像是一种**优化技巧**，而不是正则化。具体来说，当你把它与"学习率衰减"结合时，较强的权重衰减虽然起步慢，但最终能收敛到更好的解。而在固定学习率下，这种好处不一定成立。

![图注：weight decay 的反直觉——它并非在防过拟合，而是在与优化过程（尤其学习率衰减）相互作用。](assets/p03/03104.jpg)

### 8.3 dropout 与 weight decay 的取舍

讲者认为人们**基本不再用 dropout 了**，因为它与优化过程配合得并不好；而 weight decay 这种"向零收缩"的方法，可能让你能用更高的学习率、或衰减得更快。这些术语之间有很多相互关联的地方。

**教训**：这些因素的相互作用很奇怪，**很难凭空推断，必须动手实验**。这也正是这门课强调"从零构建、亲自跑"的原因。[【跳转到 49:55】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=2995)、[【跳转到 51:44】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=3104)

### 8.4 超参数总结

- 前馈层比率用 **4 倍**（GLU 时约 2.67）；
- **头维度 × 头数 ≈ 模型维度**；
- 纵横比 `d_model / 层数 ≈ 100`；
- 正则化：可尝试，但要知道它与优化器的相互作用**相当反直觉**，很多模型即使不需要也在沿用。

## 九、训练稳定性是核心问题，危险区几乎都在 softmax

### 9.1 模型越贵，越不能崩

随着训练成本越来越高，"**不崩**"变得日益重要。如果模型训练到一半突然出现难看的**尖峰（loss spike）**、梯度范数很大，最后得到的模型可能已经坏掉、再也恢复不了——你可能在训练上花了数百万美元，却到无法继续的地步。而我们希望超参数、batch 大小、正则化这些选择是"**容错**"的：调一调不会带来显著差异，那没问题；真正致命的是稳定性崩塌。[【跳转到 54:15】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=3255)

### 9.2 softmax 是危险区

语言模型里的 **softmax** 有两个特性会严重影响稳定性：

1. **指数运算**：非常容易爆炸；
2. **除法**：也是潜在的数值危险操作。

而语言模型里恰好有**两处 softmax**：一处**在输出端**（输出概率分布时），一处**在注意力机制内部**（对注意力打分做归一化时）。这两处就是模型的"危险区"。[【跳转到 55:18】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=3318)

### 9.3 输出端 softmax 与 z-loss

输出端要算对数概率：`log p = u − logZ`，其中 `u` 是模型输出（通常还算稳定），但 `logZ` 是**指数项的对数和**——它可能爆炸，也可能趋于 0，两种情况都很糟。

解决办法很巧妙：softmax 是"**过参数化**"的——**给所有 logits 加同一个常数，不会改变 softmax 的输出**（常数会在归一化因子与输出之间相互抵消）。所以我们可以**加一个惩罚项 `logZ²`**，惩罚 `logZ` 偏离 0。这招叫 **z-loss**（最早来自 Devlin 等 2014 年的工作），后来通过许多开源模型（如 BLOOM、OLMo）流行起来，DeepSeek 等模型也用这个技巧来稳定输出 softmax。它**出乎意料地有效**。[【跳转到 56:16】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=3376)、[【跳转到 57:23】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=3443)

![图注：输出端 softmax 与 z-loss——`log p = u − logZ`，用惩罚项让 logZ 尽量接近 0，从而保持数值稳定。](assets/p03/03376.jpg)

### 9.4 注意力里的 softmax 与 QK-norm

注意力里的危险在于：`Q·K` 相乘后进入 softmax，logits 可能过大。一个高层面原则是："**遇到不稳定，就在里面加一个 LayerNorm**"。这正是 **QK-norm** 的设计理念：

- **做法**：在 `Q·K` 相乘**之前**，先对 Q 和 K 各做一次 **RMSNorm**；
- **效果**：这样送进 softmax 的数值**尺度始终大致为 1**，softmax 就稳定了。

QK-norm 最初源自**多模态**领域（ViT 类的论文、Chameleon 等模型），后来被大量开源语言模型发现**完全适用于稳定注意力**。它似乎并不明显影响性能，却**能有效防止注意力退化（attention entropy collapse）**。现在 QK-norm 已成为一种非常标准的干预手段，大多数大模型都引入了它。[【跳转到 57:48】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=3468)、[【跳转到 58:38】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=3518)

![图注：QK-norm——在 Q·K 之前先对 Q、K 做 RMSNorm，让 softmax 的输入尺度稳定，从而防止注意力退化。](assets/p03/03543.jpg)

### 9.5 logit soft-cap：更强硬的做法

如果连输入都不想赌，可以直接对进入 softmax 的 **logits 做"软截断（soft cap）"**——用 `tanh` 把 logits 压在一个有界范围内，让它们永远不会太大或太小。这几乎是一种"硬约束"（虽然叫 soft-cap，但 tanh 本身就是有界的）。Gemma 系列（2/3 等）就用了这个技巧：把注意力层的所有 logits 做一次 tanh 有界压缩。

NVIDIA 的研究者对各种稳定性干预手段做过系统性比较，发现：**QK-norm 表现略好**（还能把学习率调高一些）；而**仅做 soft-cap 反而会导致性能下降**——因为它是一种非常强的干预，一旦超过某个点，softmax 就**无法表达"非常确定的信号"**了。不过它仍是一种**非常安全**地稳定"进入 softmax 的 logits"的方式。[【跳转到 59:53】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=3593)、[【跳转到 60:18】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=3618)、[【跳转到 60:43】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=3643)

### 9.6 稳定性的演进路径

一条清晰的脉络是：最初用 pre-norm 中的 LayerNorm，后来把 LayerNorm 加到每个模块的"非线性激活之后"，现在又把它用到 Q 和 K 上（QK-norm）——**这就是人们应对稳定性问题的核心工具箱**。

## 十、部署时代的两大注意力改造——GQA 与滑动窗口注意力

### 10.1 部署要花两种钱，解码阶段尤其吃亏

本讲只讨论针对"**密集全注意力（dense all-by-all attention）**"的优化，状态空间模型（SSM）与线性时间注意力留到下一讲。把训练好的模型服务给用户时，你要为两样东西付费：**FLOPs（计算量）**和**内存访问**（它影响延迟与利用率），两者都希望越小越好。

- **预填充（prefill）**：一次性把整段提示喂进去，总 FLOPs 量级约为 `batch × seq_len × D²`，内存访问约为 `batch × seq_len × D`，**算术强度高**，GPU 利用率好。
- **解码（decode）**：逐个生成 token，是自回归的固有局限——必须把过去所有 K、V 存起来，即 **KV cache**。每生成一个新 token 都要**重新读取一遍参数**，内存访问模式变得很差，**算术强度极低、内存受限**，序列越长越糟（甚至需要大批量 + 短序列，或极大的隐藏维度才能改善）。小模型的高效部署因此相当棘手。

[【跳转到 62:23】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=3743)、[【跳转到 65:35】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=3935)

### 10.2 MQA 与 GQA：把 K/V 共享起来

既然瓶颈在 KV cache 的内存访问，核心思路就是**减小 KV cache**：

- **MQA（多查询注意力，Multi-Query Attention）**：让**所有头共享同一组 K、V**，只保留各自的 Q。KV cache 大幅变小，算术强度显著提升；但**表达力明显下降**（所有 query 共用一个 key/value）。
- **GQA（分组查询注意力，Grouped Query Attention）**：折中方案——把 K、V **分组共享**，保留 Q 头的总数 H，用"K/V 头数"这个**可调比例**来在**表达力与推理效率**之间滑动。

实验（T5 时期）显示：MHA 性能最好但服务成本最高；MQA 成本低但性能明显下降；而 **GQA 兼顾两者**——只要小幅减少 K/V 头数，就能保留绝大部分性能，同时大幅降低推理成本。这解释了为什么**现在的模型几乎都采用 GQA**。DeepSeek-V2 还有一些不同的分解结构（如多头潜在注意力 MLA），留待下一讲。[【跳转到 66:18】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=3978)、[【跳转到 67:33】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=4053)

![图注：GQA 的分组结构——减少 K/V 头数、保留 Q 头总数，用可调比例在表达力与推理效率间取折中。](assets/p03/04003.jpg)

### 10.3 滑动窗口（混合）注意力：局部与全局交替

长上下文的成本很高，于是出现"**混合**"思路：**不是每一层都做全局注意力**，而是"**每隔几层用一次全注意力，其余层只看局部窗口**"。滑动窗口注意力的思想很早就有了（Longformer 提出、BERT 就用过全注意力与带状注意力交替；OpenAI 也有早期工作），但**过去一年真正流行起来**。

典型结构（以 Cohere 的 Command 系列为例）：**每四层里有一层 full attention（关注所有位置），中间三层用 sliding window attention（只看局部）**。随着层级向上推进，**局部信息逐层聚合为全局信息**。这样能控制超长上下文的成本，又不必采用状态空间模型这类"更花哨"的方案，效果相当不错。[【跳转到 71:09】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=4269)、[【跳转到 71:43】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=4303)

![图注：混合注意力——每四层中一层用全局注意力，其余层用滑动窗口的局部注意力，逐层把局部信息聚合为全局。](assets/p03/04303.jpg)

### 10.4 混合方案的更多变体与展望

一些模型（如 Llama 4 等）也采用"滑动窗口 + 全注意力"结合；还有模型（如某些开源 MoE/混合模型）交替使用**门控 DeltaNet 这类状态空间模型**与全注意力（大致每 4 层一层全注意力），用 SSM 替换局部窗口层。讲者指出：**如何平衡超长上下文与它的成本/性能，仍是当前架构最活跃的研究领域**，也是过去一年开源模型认真应对"长上下文"的新主题。到目前为止，效果最好的做法往往是这种"既不是纯全局、也不是纯廉价的**混合模型**"。[【跳转到 72:33】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=4353)、[【跳转到 72:58】](https://www.bilibili.com/video/BV11LEA6eEuj/?p=3&t=4378)

## 小结

- **架构是"表达能力 × 训练稳定 × 系统效率"三方角力的产物**：很多设计不优雅，是被现实逼出来的；这些选择几乎无法靠纯推理得出，必须靠观察大量模型 + 亲自实验。
- **被广泛采纳的核心改动其实很少**：归一化移出残差流（pre-norm）、用 RMSNorm 并去掉偏置、用门控线性单元（GLU）、用 RoPE 做位置编码。
- **RMSNorm 与去偏置是"零成本的系统优化"**：归一化算术强度低、吃内存，去掉减均值/加偏置几乎不损失表达能力却更快。
- **激活函数的关键是"门控"**：SwiGLU / GeGLU 几乎总是一致更好，为对齐参数量把前馈维度缩到约 2/3。
- **串行块优于并行块**：并行块曾因系统优化短暂流行，但相当于把深度减半、损失表达，过去两年已被放弃。
- **超参数大多有很宽的安全区**：前馈层比率约 4（GLU 约 2.67）、头维度 × 头数 ≈ 模型维度、纵横比 ≈ 100、词表单语约 3 万 / 多语 10 万~20 万；真正主导效果的是**算力（FLOPs）**。
- **正则化很反直觉**：单遍训练几乎不过拟合，**weight decay 更像是优化手段**而非正则化；这些相互作用必须实验才能理解。
- **训练稳定的危险几乎都在 softmax**：输出端用 **z-loss** 惩罚 logZ 偏离 0；注意力里用 **QK-norm** 稳定 Q·K 的尺度；更强硬的手段是 **logit soft-cap**。
- **部署时代的两大改造**：**GQA** 通过共享 K/V 大幅降低推理成本而几乎不损性能；**滑动窗口 / 混合注意力**用"全局 + 局部"交替平衡长上下文性能与成本，是当前最活跃的方向。
- **正确姿态**：别指望纯推理，**从共识里找直觉、动手实验**。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| Transformer | 2017 年 Vaswani 等人提出的、当前几乎所有大语言模型的统一骨架。 |
| 残差流（residual stream） | 贯穿网络的"主干道" `x`，各组件把计算结果加回其上，方便梯度回传。 |
| pre-norm / post-norm | 归一化放在组件计算之前（现代主流）还是之后、残差流内部（原始做法）。 |
| 预热（warmup） | 训练初期从小学习率逐步升高的做法；pre-norm 的最初动机是想去掉它。 |
| LayerNorm / RMSNorm | 归一化方式；RMSNorm 不减均值、不加偏置，更快且效果相当。 |
| 偏置（bias） | 线性层里的加性项；低性价比、吃内存，常被去掉。 |
| 门控线性单元（GLU） | 给激活加一道"门"的 FFN 变体；SwiGLU / GeGLU 是其变体。 |
| SwiGLU / GeGLU | 用 Swish / GELU 作激活的 GLU；前者为 LLaMA/PaLM 系、后者为 T5/Gemma 系常用。 |
| 串行块 / 并行块 | Transformer 块内注意力与 MLP 是先后计算还是并排计算后相加。 |
| 位置编码 / RoPE | 给模型注入顺序信息；RoPE 用"按位置旋转向量"表示相对位置。 |
| 部分旋转（partial RoPE） | 只旋转一部分坐标的 RoPE 变体，用于极小模型省显存。 |
| 前馈层比率（FFN ratio） | MLP 中间维度 / 模型维度，通常约 4（GLU 时约 2.67，LLaMA-2 约 3.5）。 |
| 头维度（head dim） | 每个注意力头的向量维度，通常 d_head ≈ d_model / 头数。 |
| 纵横比（aspect ratio） | 模型宽度 / 深度；常见 d_model / 层数 ≈ 100。 |
| 词表大小 | 分词器的 token 数量；单语约 3 万，多语 / 生产 10 万~20 万。 |
| bits-per-byte（BPB） | 用字节数归一化的损失度量，可公平比较不同分词器。 |
| 权重衰减（weight decay） | 让参数向零收缩的手段；在 LLM 里更像优化技巧而非正则化。 |
| z-loss | 惩罚输出 softmax 的 logZ 偏离 0，提升数值稳定性。 |
| QK-norm | 在 Q·K 前对 Q、K 做 RMSNorm，稳定注意力 softmax、防止退化。 |
| logit soft-cap | 用 tanh 把进入 softmax 的 logits 软限制在范围内（Gemma 用）。 |
| 注意力退化（attention entropy collapse） | 注意力分布变得过于尖锐、失去表达能力的现象，QK-norm 可缓解。 |
| KV 缓存（KV cache） | 解码时复用历史 K、V，避免重复计算；是推理内存瓶颈所在。 |
| MQA / GQA | 通过共享 K、V 降低推理成本；GQA 是折中且几乎不损性能。 |
| MLA（多头潜在注意力） | DeepSeek-V2 提出的另一种降低 KV 开销的分解结构（下一讲）。 |
| 滑动窗口注意力 | 只关注固定局部窗口的注意力，常与全局注意力交替使用。 |
